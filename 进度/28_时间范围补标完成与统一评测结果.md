## 1. 本轮完成的工作

使用 tls 环境，读取已有 .env 配置，将授权的 Yemen、MJ、David Bowie 共 221 篇正文片段及对应事件信息发送至 https://api.deepseek.com，模型为 deepseek-v4-flash。每篇正文最多 698 字符，没有扩大候选范围。

按事件特定 pooling 补齐 250 个关系，合并到原有 2,532 条 qrel，最终得到 2,782 条唯一判断。随后对同一 29 个 dev 事件重新执行 none、soft、hard 三种检索模式，并通过独立审计确认全部 87 组排名与补标前一致。

## 3. 同一 qrel 下的评测结果

实验设置：29 个事件、固定 v3 混合索引、Gold 事件摘要作为 evaluator query、以 Gold 日期为中心的发布日期 ±14 天窗口，soft_penalty=0.5。

| 模式 | Recall@20 | nDCG@20 | MRR | 已标注/返回 | 未标注 |
|---|---:|---:|---:|---:|---:|
| none | 0.8072 | 0.6365 | 0.5026 | 580/580 | 0 |
| soft | 0.8700 | 0.7733 | 0.6529 | 580/580 | 0 |
| hard | 0.7273 | 0.6931 | 0.6494 | 397/397 | 0 |

当前指标实现中，Recall 和 nDCG 对存在 Grade 2 正例的 21 个 resolved 事件取平均；MRR 和 Success 对全部 29 个事件取平均。其余 8 个事件在现有池中仍无 Grade 2，不能据此认定冻结语料一定不存在相关证据。

soft 相对 none 的 Recall@20 提高 6.28 个百分点，nDCG@20 提高 0.1368。soft 与 none 的 Success@20 都为 21/29，因此该实验体现的主要是已知事件的证据覆盖和排序改善，没有增加最终命中的抽样事件数。

补标前 none Recall@20 为 0.8472，本轮为 0.8072，原因是共同正例池扩大而原排名保持不变。必须使用本轮统一 qrel 横向比较，不能将不同 qrel 版本下的 Recall 直接作性能增减比较。

## 6. 对研究方案的影响

本轮支持继续采用“第一阶段全局探索 none；第二阶段针对有时间锚点的 gap 尝试 soft；hard 作为可选动作和消融”的路线。当前运行时默认仍为 none，尚未把 Gold 日期窗口接入真实 Agent。

需要保留以下实验边界：

1. 这里的 query 和窗口中心来自 evaluator Gold；真实 Controller 必须根据当前时间线和 Memory 预测窗口。不能将 0.8700 写为真实 Agent 的检索或时间线覆盖率。
2. soft 的当前实现还扩大了候选池，收益可能同时来自时间偏置与更深候选。下一项应加入相同候选深度的对照，分离两种影响。
3. 只有三个 dev 主题、一个窗口和惩罚设置，尚未证明参数最优或统计显著。
4. dev qrel 用于检索评测和开发选择；正式 SFT/DPO 样本应来自 train 主题，避免把这些 dev 标注直接当训练集。

下一步优先将日期参数接入 GAP_REFINEMENT 的 SEARCH action，并通过实际无 Gold 输入的 Controller 轨迹验证时间窗口；再在 train 主题构造 query、SEARCH/STOP、Memory 更新的 SFT/DPO 数据。
