# 第一阶段补充及相关改进的可行性评估

范围：基于已有 27 个主题的离线数据和当前代码；不修改运行框架、不启动 API、不执行并行任务。本方案可行，但不能直接以最长时间空档定位遗漏，也不能把发布日期过滤当事件日期过滤。

## 数据依据

第一阶段漏掉 923 个 Gold 日期，其中 846 个位于其预测跨度内部；原第二阶段最终保留 1264 条新增事件，首次命中其中 154 个日期，即恢复 16.68%。最终 771 个遗漏中 718 个位于预测跨度内部。这支持增加区间内独立探索模块，但不能证明该模块必然带来某个幅度的提升。

只用第一阶段日期、固定选择各主题最长的 3 个内部空档，选择结束后才用 Gold 做离线诊断：所选区间合计包含 141/923＝15.28% 的第一阶段遗漏日期。这是候选区间定位结果，不是实际检索召回率。T17 Iraq 所选三个区间全部位于 2005 年以前，包含遗漏 Gold 日期为 0；Crisis Syria 被 1946—2000 年的背景事件长空档吸引，同样为 0。Bill Clinton 包含 9/43，Beckham 3/16。此诊断没有调参，不构成最优区间选择器。

诊断产物：`chronos_repro/artifacts/supplement_feasibility_20260917/naive_interval_diagnostic.json`。

## 1. 第一阶段补充：有条件可行

### 区间识别

“强行定位”可以实现为确定性产出待探索区间，但不能把统计分数说成已经确认遗漏。零事件可能是正常静默，事件多也可能仍有大量漏失。需要联合：

- 区间内主题相关独立文档或去重段落的事件时间信号；
- 区间内已验证事件日期的覆盖密度；
- 区间内未完成抽取、未读高相关证据的数量；
- 近期检索增益与已用预算。

建议先固定月/季度基础分箱，再按证据量合并或细分；对各项做主题内排序归一化，优先选择“相关证据活跃、已有事件相对少、未处理证据多”的区域。不是采用统一事件数阈值，也不是只选零事件区间。先验权重和阈值需要离线验证，当前没有实测最优值。

候选范围来自语料元数据、事件时间标注和已召回证据，不使用 Gold 起止作为在线边界。不能只取第一阶段最早—最晚事件，否则其外的遗漏永远没有机会。发布日期活跃只能作为辅助线索，不能冒充事件密度。现有 final reader manifest 含第二阶段信息，评估第一阶段选择器时必须重建第一阶段可见证据，不能拿最终证据回填导致信息泄漏。

区间采用 [start,end) 或逐日互斥闭区间，确保边界日期有且只有一个归属。

### 独立初始化

每个区间 timeline、memory、query history、gap memory 都初始化为空，只保留主题、区间边界、冻结语料和必要任务参数。这样能减轻原摘要偏向已有故事的问题，但也会增加重复抽取，区间之间不得共享可变模型状态。不能指望独立初始化自动消除日期错误或保证更高覆盖。

### 硬范围限制：当前存在明确语义冲突

当前 `temporal_filter.py`、retrieval 和 EvidenceReader 的 hard 时间范围都是 publication_date，不是事件发生日期。已有第一阶段事件证据例子：

- Beckham 的 2001-10-06 事件，证据 publication_anchor 为 2006-07-03。
- Clinton 的 1993-01-21 事件，证据 publication_anchor 为 2004-11-18。
- Clinton 的 1993-11-17 NAFTA 众议院表决，证据 publication_anchor 为 2008-03-19。

如要求文章发布日期也不得超出区间，技术上能执行，但这些回顾证据将被排除，不能保证召回改善。建议把“本区间任务”的硬约束定义为事件发生日期；允许支持区间内事件的回顾报道。若用户实际要求发布日期硬限制，也必须尊重该要求并单独量化损失，不能静默放宽。

按事件日期硬限需新建或扩展段落事件时间候选索引/校验，现有 publication filter 不能原样充当实现。日期标注只用于证据候选定位，最终仍须 VERIFY 核验原文。只在最终入库过滤虽然能限制输出，却不满足所有检索实际受限的要求。

模型给出的时间范围必须与所属区间取交集；未给范围则用所属区间，交集为空就记录无可执行范围，不允许退回无限制检索。检索、选段、候选校验、MERGE 入库都要记录所属区间和有效范围。新确认日期落到其他区间的候选交协调器暂存裁决，不允许当前 worker 越界检索。

### 并行及合并

可从 2 个独立区间 worker 起步；这只是建议，未测试吞吐。当前账本是单客户端读写 JSON，并非并发共享计数器；每区间需独立 output/ledger/cache 写域，由协调器预分配预算并汇总余额停止信号。不能多个进程同时写一个账本。使用唯一命名空间事件 ID，保留父来源与输入快照。

区间不重叠只能避免同一日期归属冲突，不能避免同一事件被错定到不同日期。且补充事件仍会与原第一阶段事件重叠。因此不能只按时间拼接：确定性去重→语义重复/日期冲突裁决→统一排序。原始事件和新证据都应保留来源，不应为合并而覆盖旧轨迹。

## 2. 优先续读高价值未完成证据：可行，改动相对集中

当前已有 incomplete_extraction、candidate_pool、already_extracted、extraction cache，可用于精准续读。已有 1204 条未完成记录不能直接当作独立段落数：需要按 passage ID/内容哈希去重、核对是否后来完成，再形成待处理队列。

优先级考虑主题相关性、区间内新日期线索、已支持但抽取不完整的证据；不应只按错误次数排序。页数不足或 has_more 的条目适合追加抽取；持续格式/引文验证失败应先修复或隔离，不盲目重试。沿用已提取候选排除重复，成功完成后才标 processed。

第一阶段补充如果完全复用目前第一阶段代码，仍会沿用 coarse_extraction=true、最多 1 页，可能重现原不足。需要保留粗探索策略，同时给高价值未完成证据增加独立的有界精读队列。区间模型 memory 仍为空；原段落的抽取进度属于执行器证据队列，不能偷偷把旧全局摘要注入 worker。

## 3. 日期冲突单独裁决：可行，且是区间合并的前提

优先处理高相似事件但日期不同的候选，读取双方原文、日期表达和归一化依据，区分发生日/公告日/报道日/多日事件。输出保留原日期、接受修正日期、拆分为不同事件或证据不足待定；不能强行二选一、用发布日期补事件日或只按 Gold 改日期。

已观察到 Charles Taylor 6 月 20 日候选被视作 6 月 19 日事件重复，Snowden 6 月 5 日候选被视作 6 月 6 日事件重复。这支持设置专门裁决路径，但现有记录不能证明每次都应改成 Gold 日期。仅对冲突触发，避免每次 MERGE 都增加请求。

## 4. 第二阶段增加搜索次数：可行，但应先纠正预算单位

25/27 个主题第二阶段撞到全局批次上限。423 个 DEFERRED 都是 query 次数上限，其中 412 个仅搜索 1 批。因为一批最多 3 条 query，per-gap 上限也是 3 条 query，因此不能把它理解成已有 3 轮搜索。

建议单独设置 max_queries_per_batch、max_batches_per_gap、max_total_phase2_batches，并保留累计请求预算。试验起点可以是每 gap 2—3 批、每批最多 3 条，但这只是待测配置，不是已证明最优预算。根据新事件/有效证据/重复率决定是否再给一批；无值得继续检索的问题仍可停止，不需要为了用完次数制造 gap。

不应一边把区间数乘上原 24 轮，一边提高全局第二阶段上限而不计总成本。VERIFY 虽已有不设请求数限制的授权，也必须纳入 token 与请求统计。并行只可能缩短墙钟时间，不会自动减少 API 成本。

## 推荐框架与验证

第一阶段基线冻结 → 高价值未完成证据续读 → 统计定位独立候选区间 → 区间内独立第一阶段补充 → 全局去重/日期冲突裁决/排序 → 刷新全局 memory → 第二阶段按明确的批次预算补 gap。

可将续读、区间探索和汇总整体归为“第一阶段补充”。统计定位在续读后更新，避免已经补齐的区间继续占预算。所有增量与原第一阶段分开记录，方便比较。

先用固定第一阶段快照做小规模对照，至少覆盖 T17 Iraq、Entities Bill Clinton 或 Beckham、Crisis Egypt；同样数据和总预算下分别检查区间探索、续读、日期裁决、增加第二阶段轮数的增益，避免四项同时改完就无法归因。Gold 仅用于运行后评测。保留输入预检 3800、上限 4096 tokens。

报告新增且最终保留事件、新增 Gold 日期微/宏平均、旧命中损失、日期冲突人工核验、越界计数（应为 0）、input/output/cache tokens 和实际账单费率。训练门禁继续保留。当前只有离线区间诊断与实现核查，没有在线收益、成本或并行安全验证结果。
