## 一、固定配置

新增 `chronos_repro/configs/retrieval_baseline_v1.json`：

- 检索器：SQLite FTS5/BM25；
- 标题权重 2.0，正文权重 1.0；
- query operator：OR；
- top-k：20；
- 最大检索轮数：3；

这份配置先固定不依赖模型的实验条件，避免在选定 LLM 前把启发式检索烟测误写成 CHRONOS 模型结果。

## 四、轨迹结构

新增 `trajectory.py`，每轮保存：

```text
state
  → action {type, query, top_k}
  → observation {results, new_doc_ids}
  → updated_state {seen_doc_ids, document_count, new_document_count}
```

整个轨迹还保存索引绝对路径、索引 SHA-256、快照元数据、停止原因和固定配置。`replay-search` 会先校验索引哈希，再重新执行每轮 action；结果有任何变化即失败。

真实 Crisis/Egypt 轨迹运行 3 轮，最终停止原因为 `max_rounds`，随后逐轮重放完全一致：

- `artifacts/crisis_egypt_trace_v1.json`
- `artifacts/crisis_egypt_trace_v1_replay.json`

## 五、新增命令

```powershell
chronos-repro trace-search `
  --index artifacts\crisis_ece08f344cc94933.sqlite3 `
  --search-engine "crisis egypt" `
  --query "egypt crisis timeline" `
  --query "Hosni Mubarak resignation protests" `
  --query "Egypt presidential election Morsi" `
  --top-k 20 --max-rounds 3 --stop-no-new-rounds 2 `
  --output artifacts\crisis_egypt_trace_v1.json

chronos-repro replay-search `
  --trajectory artifacts\crisis_egypt_trace_v1.json `
  --output artifacts\crisis_egypt_trace_v1_replay.json
```
