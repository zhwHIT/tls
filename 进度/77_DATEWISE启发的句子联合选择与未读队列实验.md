# DATEWISE 启发的句子联合选择与未读队列实验

日期：2026-09-18。范围为 Beckham 原始 v9.7 第一阶段的 51 条历史 query、原 top-12 结果及历史复用文档；不包含 v10 补充或第二阶段。本轮是离线选择实验，API 调用 0，不修改生产 reader、运行配置、原始轨迹或 Gold。

## 主指标更正：全部 Gold 日期覆盖率

根据用户明确要求，方案优劣的主指标为 **Gold 日期覆盖率 = 第一阶段最终事件日期与全部 Gold 日期的去重交集大小 / 全部 Gold 日期数**。本主题分母固定为 **16**，不能缩为已经找到证据的三个事件，也不因语料时间截断移除任何 Gold。沿用项目 `evaluate_dates` 的严格日级日期召回口径；该指标本身不要求摘要语义相同，日期对应的事件是否正确需在逐项审计中另外报告。

|方案|命中全部 Gold 的日期数|Gold 日期覆盖率|
|---|---:|---:|
|原始第一阶段最终事件库|0/16|0%|
|联合选句，不启用跨查询队列|未测|未测|
|联合选句，启用跨查询队列|未测|未测|

[gold_coverage.json](../chronos_repro/artifacts/beckham_sentence_queue_offline/gold_coverage.json) 保存全部 16 个日期、基线重算结果及各方案未测状态。两种历史导语方案也没有重新经过抽取、日期验证和合并，Gold 覆盖率同样未测。下文的 2/3、37/45 等只用于定位选句机制，不再作为方案有效的主结论，也不能换算成已实测的 2/16。

后续正式对照须让冻结的选择结果经过同一配置的抽取、日期验证与合并，再对最终事件库评测全部 16 个日期。各组状态隔离，Gold 只进入评测端；如果下游模型或代码不同于历史版本，原选择也必须在同配置下重跑，历史 0/16 仅作为参考。保持相同证据预算，并另外报告实际调用量和费用。当前离线选句实验尚未完成这个主指标的对照评估。

## 设计

借鉴 DATEWISE 将报道开头与日期提及句结合的思路。本实验没有复现 DATEWISE 的完整日期排序、P/M 日期集合、PM-MEAN 日期向量或最终摘要流程。

原 top-12 合计 209 篇去重文档，按冻结正文换行位置得到 5661 个句子候选单元，其中前五句候选 990 个、含时间提示的单元 930 个。短碎片与后续单元合并，开头代词或前句不完整时保留前一单元。这里不重新运行 NLP 分句，因而单元不保证总是完整的语言学句子。

每条 query 联合考虑三类来源：

1. **原相关句**：位于原来选中段落及连续前文中的句子，兼顾 query 词匹配、主题、时间提示与位置。
2. **主事件候选句**：已召回文章的前五个句子单元，按主题匹配、标题匹配、query 匹配及召回排名评分。它们不是经过模型确认的主事件。
3. **日期提及句**：正文中包含具体年份、月份、星期、today/yesterday/last night 等时间提示的句子。时间提示只用于安排阅读，不做规范化或日期入库，也不将发布日期替代事件日期。

分配时先尝试在总 token 预算的 45% 内选原相关句，再在累计 75% 内选主事件候选，最后在完整预算内选日期句。剩余空间由三类候选轮流补充。这些是容量上限和选择顺序，不保证每类最终恰好占对应比例，也不是已经证明最优的参数。

选中内容之间施加词面冗余惩罚；历史候选得到有上限的等待时间加分。评分不读取 Gold、诊断事件标签或历史 VERIFY 的 SUPPORTED 结果。上述参数在本轮执行前固定，不按本轮得分调整。

## 两个新对照组

|组别|可选择的文档|共同机制|
|---|---|---|
|联合选句，不启用跨查询队列|当前 top-12，以及原记录当次已经选中的历史复用文档|三类候选、同一评分和预算、已展示源区间不重复选择|
|联合选句，启用跨查询队列|截至当前已经召回的所有文档|同上；此前未选中的源句仍可在后续 query 获得阅读机会|

两组都保留展示历史；差别是此前未选中候选的可用范围。无队列组仍沿用原轨迹当次的历史复用结果，因此它不是完全无记忆的搜索。

未读状态以候选 ID 和原文区间记录，不把“文章读过一句”当成整篇读完。预算放不下的完整句子保留在未读记录里，不截断、不当作已读。落盘状态用于检查本次选择历史，尚未接入生产重启恢复。

## 同预算的定义

所有对照统一表示为“文档来源＋一个或多个带原文偏移的连续片段”。不连续的句子分开存放，只有重叠或首尾直接相接的区间才能合并；中间缺失的文本不能冒充已经提供。

新策略每条 query 的上限取原选择在同一表示下的实际 token 和可见字符数，文档 ID、正文哈希、标题、发布日期、每段起止位置和文本均计入 token。上一轮两种导语方法也在同一表示下重新计算，不能直接与上一轮 31,830 等旧投影数字混用。

本次允许多个短句片段，而不再限定两个连续段落。预算比较针对证据输入，未包括完整 VERIFY 系统提示、时间注释、动态 Memory，也没有模拟增加片段后实际调用次数的变化；因此不宣称 API 成本持平。

## 评估范围

沿用上轮九个逐字证据标注，覆盖退役、百场国家队比赛、银河首秀三个诊断事件及两个预告线索。事件描述、相对日期提示、预告分开计数；不把预告当成已发生事件。

同时核对历史 45 条 SUPPORTED 候选引文。主要报告“至少有一次 query 的输入完整包含该引文”的数量，不要求仍在原来的 query 出现；另存跨整个运行的区间并集结果。跨 query 拼起来才完整的证据不能冒充同一次模型已看到。45 条中包含重复和历史日期错误，因此保留率不是事实正确率。

查询序列仍固定为历史 query，即使新段落可能影响后续搜索，也不改变它。这是已观察开发主题上的机制诊断，不是盲测、完整 Agent 运行或最终 Gold 日期召回测试。

### 三个诊断事件

- **退役，2013-05-16**：两种联合选句均在 query 1 选中 doc 18349 的标注事件句，在 query 2 选中 doc 18406 的标注事件句。队列组额外在 query 7 选到 doc 18348 的同一事件证据，属于重复佐证，没有增加独立事件覆盖。
- **第 100 场国家队比赛，2008-03-26**：两种联合选句均在 query 2 选中 doc 19367 的事件描述和 `last night` 日期线索，而且两者在同一次输入中同时可见。这是相对原选择和两种导语方案的明确证据覆盖增量，仍需 VERIFY 验证事件与日期关系。
- **银河首秀，2007-07-21**：两组都未选中 doc 19197 的标注事件句及 `Saturday night` 线索。文档在 query 35 排名第 7；队列组到运行结束仍保留事件句 `[0,161)` 和日期句 `[502,731)`。它们分别累计有 49 和 83 次预算检查未通过，计数包括各选择轮次，不等于 query 数。query 35 已使用 703/710 tokens，先选了原相关来源 doc 18470 的四个单元，另选其他文档的开头及日期句。因此本次未命中不能归因于候选过期丢失；保留候选仍不足以让它在当前评分、选择顺序和剩余预算下被阅读。

两组还选到 PSG 预告线索，但未计入已发生事件。不能将这些离线结果写成“Gold 从 0/16 提升到 2/16”。

补充核算：doc 19197 的首秀事件句单独连同完整来源信息为 131 tokens；事件句和上述日期句一起为 187 tokens、390 个正文字符，低于 query 35 的 710-token/2,157-character 总上限。它们并非单独就放不下，而是未能在当前逐项选择过程中获得所需的剩余空间。这个核算仅解释预算竞争，不据此按 Gold 标签强制挑选该文档。

### 队列收益与代价

启用队列后，实际阅读文档从 115 增至 148。独立检查找到 129 次候选选择来自“既不在当前 top-12，也不是原记录当次复用文档”的历史来源，证明跨 query 候选确实获得了阅读机会。最终队列仍有 5,233 个未读单元；无队列对照的状态记录有 5,211 个，但这些旧单元只有文档再次进入当次可用范围时才能参与选择。文档覆盖增加与剩余单元更多并不矛盾：队列组阅读分散到更多文档，不能以文章被访问代替句子已读。

本轮没有观察到队列对三个诊断事件的额外覆盖收益，历史引文保留还从 37/45 降为 36/45。相对原始选择，队列方案少保留 9 条历史引文。短句片段及更多来源也带来额外元数据开销，因此相近 token 下正文字符明显少于原始选择。这些结果支持继续研究句子联合选择，但不足以直接替换主流程。

后续实验优先检查“事件句与日期句共同入选”和“等待候选获得预算机会”的调度机制，并监控旧证据损失；不继续扩大整块导语比例。本轮固定权重未根据结果重调，也未将三个诊断标签写入选择逻辑。

### 验证与运行边界

[validation.json](../chronos_repro/artifacts/beckham_sentence_queue_offline/validation.json) 记录独立验证：五组结果重新分词计费一致，两种新方案每条 query 均满足预算；历史输入文件哈希保持不变；原文偏移、禁止跨缺口拼接和禁止使用未来召回文档的检查通过；合成用例验证候选跨 query 保留，以及超预算整句不会截断或误标已读。

从策略文件写入到报告写入约 517.6 秒（8.6 分钟），包含本次离线选择与评估，不是逐组耗时或线上延迟。当前实现反复计算候选组合 token，尚需性能优化。没有调用模型 API，没有重新运行 VERIFY/MERGE，也未修改生产 reader、主配置和原始实验结果。
