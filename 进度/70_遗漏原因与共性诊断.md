# 遗漏原因与共性诊断

范围：已有 27 个主题。基于保存轨迹、Gold 日期与文本、gap 状态、证据读取计数和代码机制；本次 API 调用 0，不修改运行框架与历史产物。以下是证据支持的共性，不是对全部 771 个遗漏逐一完成的因果归因。

## 1. 已有事件驱动的 gap 发现，容易遗漏独立的重要事件

直接观察：gap 契约要求问题锚定可见事件及逐字摘要引文，不允许仅因时间间隔大就制造 gap；749 个 gap 中 701 个只有单锚点。现有示例中，Bill Clinton 的遗漏含当选、就职、Brady 法案和 NAFTA，而部分 gap 在追问手术、助选安排、基金会捐款披露；Beckham 的遗漏含首秀、队长任命和荣誉，而部分 gap 在追问伤病、红牌及是否归队。T17 Iraq 的 Gold 中存在大量 2005 年逐日暴力事件，部分 gap 则追问 1993 年军事行动细节和个别审判后续。

推断：第一阶段若未触及某一事件支线，第二阶段依赖已有锚点的方式较难主动发现它；对已有故事的追问可能继续增加事件，却未必覆盖 Gold 所强调的重要里程碑。这是探索目标与局部补全目标的分工问题，不意味着所有这些 gap 都无价值，也不应强行按 Gold 制造 gap。

## 2. 查询上限与批次定义叠加，很多 gap 实际只搜索一轮

直接统计：第二阶段 25/27 个主题因 runner_limit 结束；剩余 2 个为 no_actionable_gaps。423 个 DEFERRED 全部标注 query_attempt_ceiling_not_resolution。其中 412 个恰好执行 1 批搜索，11 个执行 2 批。还有 249 个 OPEN gap 没有 attempted_queries。

代码机制：一次 SEARCH 最多输出 3 条 query，每条都会加入 attempted_queries，而 per-gap 上限是 3 条 query，不是 3 批。因此一批 3 条 query 就可能用完该 gap 的额度，尚无机会根据首轮返回改写搜索。全局 18 个 gap 搜索批次又限制了任务队列的处理量。

推断：预算不只是“总量不够”，还可能同时出现单 gap 过早耗尽、局部任务占用预算、其他 gap 未轮到。不能据此保证简单加轮数就能提高覆盖率。

## 3. 找到文档不等于完整抽取其中所有事件

各主题的 evidence_progress 相加：已知文档 6963，已知段落 42640，标记 processed 的段落 3168（7.43%），其余 39472。这个统计是按主题累计的 reader 状态，不是全语料的唯一段落数，也不是模型实际读取率。未标记 processed 的段落可能尚未选择，也可能存在未完成抽取。

另有 1204 条 incomplete_extraction 记录：1068 条写明 extraction page limit reached，136 条为 page limit or unresolved validation。记录可能包含同一段落的重复尝试，不能当成 1204 个独立漏失事件。

当前代码对第一阶段采用粗抽取、每批段落最多 1 页，第二阶段最多 2 页；历史运行版本不同，不能用最新代码替代全部历史细节。上述计数支持段落选择和抽取完成度是需要排查的瓶颈，但没有证明未处理段落里究竟有多少 Gold 证据。

## 4. 精确日期和 MERGE 去重确实造成部分命中损失，但不足以解释多数遗漏

771 个最终遗漏日期中：20 个曾出现在保存的 VERIFY 候选，17 个曾在 passed_candidate_ids 对应候选中出现；10 个出现在最新 quarantine 记录；15 个有同日候选被 MERGE DROP。集合有交集，不得相加。这些只是日期重叠，不保证候选与 Gold 是同一事件。

保存的 DROP 理由里能看到具体问题：Charles Taylor 2006-06-20 的转移海牙候选被当成已有 2006-06-19 事件的重复；Snowden 2013-06-05 的披露候选被当成已有 2013-06-06 事件的重复。它们表明日期冲突可能被重复判定带过，需要回到原文裁决，不能机械采用 Gold 日期或放松日期证据。

此前审计还发现 3 个第一阶段命中日期最终消失，其中 2 个由 UPDATE 改日期、1 个由筛选移除。日期命中下降可能是错误，也可能是在纠正旧日期，不能单凭这一点判断事实质量。

对于另外 751 个日期，仅能说在保存的成功 VERIFY 步骤候选中未出现；不能直接断定是检索失败，因为原始证据是否被选中、失败响应、抽取遗漏和日期表达差异尚未逐一对齐。

## 5. 局部问题可结束，不代表主题时间线已经充分覆盖

David Bowie 第二阶段 no_actionable_gaps 时仍遗漏 4 个 Gold 日期，Dilma Rousseff 同状态时仍遗漏 8 个。该状态表达当前 gap 队列没有可执行项，不是完整性证明；DEFERRED 也不等于 RESOLVED。应保留“没有值得继续检索的问题时可以停止”的原则，同时单独报告覆盖质量与未处理证据。

## 共性结论与优先级

最值得验证的共同机制是：第一阶段探索集中于部分故事，第二阶段围绕这些已有故事进行局部追问；查询额度和段落抽取限制使系统较早停止，仍未触及其他重要事件。日期处理及去重还会造成少量可见损失。此机制与“新增事件很多、新增 Gold 命中有限、遗漏主要在跨度内部”的结果一致，但尚非受控因果实验结论。

建议优先：

1. 分开记录“已有问题补全”和“尚未探索的主题/时期线索”，后者必须来自语料、检索结果或明确证据，不使用 Gold 作为在线提示，不把长时间空档自动当 gap。
2. 将每批 query 数、每个 gap 的搜索批次数和全局批次预算明确分开；根据实际增益与剩余证据调度，并检验是否需要给第一批后的查询修正留预算。
3. 在继续发新搜索前优先评估已召回但未完成抽取的高价值段落；只对 has_more/未完成证据做有界续读。
4. 对“同事件但日期不同”的 MERGE 引入明确的日期冲突裁决，不用普通重复丢弃代替证据核验。
5. 用固定主题配对实验验证上述改变，分别报告新日期收益、语义事件质量、token/请求成本和停止原因。不要仅增加 VERIFY 次数或放开所有上限。
