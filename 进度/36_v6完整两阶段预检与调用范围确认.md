## 2. 为什么先补完整入口的保护

上一轮只有固定片段烟测接入了持久请求计数；完整两阶段入口仍按每次启动重新计数。若发生输出校验失败后重启，可能超出用户为一次实验批准的累计调用量。

现在 coverage-enabled 的完整入口：

- 默认拒绝 API 运行；需要 `--dry-run` 或明确的 `--allow-api`。
- `--dry-run` 在加载 `.env` 和创建 API 客户端之前返回，只检查 `.env` 文件是否存在，不读取密钥，不查询余额。
- 完整 API 模式采用输出目录中的 `request_ledger.json`，每次 HTTP 尝试前记账，重试也计入，重启后沿用。
- 已完成或已记录余额不足的运行不能直接重启；有历史结果或缓存、但没有累计账本的旧目录也拒绝继续，不根据缓存数量猜测历史请求量。
- 对配置、混合索引清单、Dense 清单和快照清单记录 SHA-256，绑定到 `run_binding.json`。输入绑定改变时拒绝复用同一运行目录。
- 最终 `trajectory.json` 和 `manifest.json` 都记录本次启动请求数和跨启动累计请求数。

注意：完整两阶段入口仍主要通过缓存重放恢复，不等于已经支持从任意阶段检查点直接续跑；本轮没有将烟测的任意批次恢复机制扩大为完整两阶段状态恢复。不得让多个进程并发写入同一个运行目录。

## 4. 下一步完整实验的拟调用范围

这是待确认的完整实验范围，**不是本轮已经获得或执行的额外调用量**。

| 范围 | 设置 |
| --- | --- |
| 数据 | 仅 Crisis/Egypt 冻结语料，检索后选择相关片段，不把 4,083 篇全文全部发送 |
| 端点 / 模型 | `https://api.deepseek.com` / `deepseek-v4-flash` |
| 第一阶段 | 最多 16 轮搜索，包含粗阶段 Memory 与自主 SEARCH/STOP |
| 第二阶段 | 最多 12 个 gap 处理周期，最多记录 24 个 gap |
| 片段选择上界 | 最多 28 轮 × 8 = 224 个片段选择槽位 |
| 单片段正文 / 前文 | 最多 3200 / 400 字符，另含标题及来源元数据 |
| 其他输入 | 历史 query、Memory、候选事实、已有时间线及相应证据引文 |
| 累计请求上限 | 本次完整实验最多 400 次 HTTP 请求，包含校验修复、传输重试和重启 |
| Gold | `phase2_teacher_guidance=false`，不发送给模型，不用于指定检索日期 |
| 余额不足 | 立即停止，持久记录后禁止继续调用 |

224 是片段选择槽位上界，不是 224 篇独立文档，也不是所有 HTTP 消息的字符总上限。同一片段及其派生状态可能在分页、修复、合并和后续决策中重复发送。400 是安全上限，不是预计一定花满，也不能保证在上限内完成或达到覆盖目标。

上一轮烟测的 17/30 次请求保持不变；不能把剩余 13 次自动挪作本次不同外发范围的完整实验。新实验将在独立目录 `artifacts/tisa_coverage_egypt_v6/` 留存结果。

## 6. 完整试跑后的验收顺序

1. 先核对 HTTP 账本、余额停止状态与来源审计。
2. 检查第一阶段是否按不同时间段发散，合并后 Memory 是否保存有效阶段和未定日期线索。
3. 检查 GAP_MEMORY、gap 调度与搜索补充是否实际推进，区分自主停止和安全上限中断。
4. 单独检查 UPDATE 是否真实触发，融合是否保留来源、日期及事实；烟测中 UPDATE 未触发。
5. 对比事件池和最终时间线的 Date-P/R/F1、缺失 Gold 日期，并做独立事件语义核验；暂以日期召回 70% 为工程目标，不以高精度替代覆盖率。
6. 只有有效且完整的决策轨迹通过数据隔离检查后，才决定是否导出用于 Controller 的 SFT/DPO 样本。
