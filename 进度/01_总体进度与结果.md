### 2.3 实现 Open-TLS 安全读取

上游 CHRONOS 使用 `eval()` 读取时间线，这会执行任意 Python 表达式，不适合作为稳定的数据加载器。新实现优先使用 `json.loads()`；为兼容旧 TLS 语料的 Python literal 格式，仅使用安全的 `ast.literal_eval()` 作为回退。

已经支持：

- `YYYY-MM-DDT00:00:00`；
- `YYYY-MMT00:00:00`，映射为当月 1 日；
- `YYYYT00:00:00`，映射为当年 1 月 1 日；
- 同一日期多条事件合并；
- UTF-8/UTF-8 BOM；
- Open-TLS 格式和 CHRONOS 保存的预测格式。

### 2.4 实现评测

当前支持两层指标：

1. Date Precision、Recall、F1；
2. Tilse 的五种 Timeline-ROUGE 变体：Concat、Agreement、Align、Align+、Align+ many-to-one。

金标准回灌测试使用 Open-TLS 的 `Islamic_State_2019.10.27`：把其金时间线同时作为预测与参考，Date-P/R/F1 均为 1.0，便携版全部 Timeline-ROUGE-1/2 也均为 1.0。

原版 `tilse` 默认调用 Perl ROUGE 脚本。在原生 Windows 上，Python 把 `.pl` 文件直接当成 Win32 程序运行，产生 `WinError 193`。为此增加了明确的评测后端参数：

- `original`：论文兼容的 Perl ROUGE，需要 Perl/Linux/WSL；
- `reimpl`：Tilse 自带的 Python 近似实现，可在 Windows 运行。

结果 JSON 会记录 `rouge_backend`，避免把近似分数误当成论文严格可比分数。

### 2.5 实现并验证语料冻结

冻结工具会：

1. 递归扫描源语料；
2. 计算每个文件的 SHA-256 与大小；
3. 对排序后的文件清单计算内容 ID；
4. 复制到临时 staging 目录；
5. 比较复制前后的清单，防止复制期间源数据改变；
6. 生成 `MANIFEST.sha256.json`；
7. 将 staging 原子重命名为最终快照目录；
8. 重复冻结相同内容时返回同一个快照，不重复复制。
