## 二、新增和修改的文件

### `src/chronos_repro/corpus.py`

定义 Crisis=4、T17=9、Entities=47 的预期主题数；对每个主题检查以下三个文件：

- `articles.preprocessed.jsonl.gz`：全量解压、逐行 JSON 解析，并要求 `id/time/title/text/sentences` 字段；
- `keywords.json`：要求非空字符串列表；
- `timelines.jsonl`：调用统一安全读取器，验证日期和事件结构。

Crisis 和 T17 还校验官方主题名集合。`--quick` 只读每个压缩包的第一条记录，适合快速排错，正式冻结前仍应使用默认全量模式。

### `src/chronos_repro/batch.py`

按 `<topic_id>.json` 查找预测文件，逐主题调用既有评测函数，计算每个数值指标的跨主题算术平均。默认缺少任一主题即失败；调试时可显式使用 `--allow-missing`。

### `src/chronos_repro/provenance.py`

统一生成评测证据链：UTC 时间、Python、操作系统、ROUGE 后端、CHRONOS 上游 commit、数据绝对路径；若数据目录位于冻结快照内，还会自动发现 `MANIFEST.sha256.json`，记录数据集、snapshot ID 和 manifest 哈希。

### `src/chronos_repro/cli.py`

增加 `validate-corpus` 与 `evaluate-batch` 子命令。单主题 `evaluate` 也写入预测文件 SHA-256。`freeze` 现在默认先做完整语料校验，校验失败拒绝冻结；`--skip-corpus-validation` 仅作为非标准自定义语料的危险逃生口。

### `scripts/export_gold_predictions.py`

为每个主题导出第一条参考时间线，专门用于批量管线烟测。文件头已明确标注 gold leakage，不能作为 baseline。

### `tests/test_corpus.py` 与 `tests/test_batch.py`

新增完整/不完整 Crisis 布局测试，以及两主题批量日期评测与预测哈希测试。当前全部自动测试结果为 `8 passed`。

### 新增产物

- `artifacts/crisis_corpus_validation.json`：Crisis 全量强校验报告；
- `artifacts/gold_predictions_open_tls/`：50 个仅用于烟测的金标准预测文件；
- `artifacts/open_tls_batch_gold_date_smoke.json`：批量日期指标及完整溯源元数据。
- `artifacts/t17_partial_validation.json`：明确检出缺少 `syria` 主题，且 `mj` 缺时间线；
- `artifacts/entities_partial_validation.json`：明确检出仅 2/47 个目录，且 `Angela_Merkel` 三个必要文件均缺失。

校验 Entities 时还发现其已下载时间线使用 `YYYY-MM-DD HH:MM:SS`。安全日期解析器已补充该官方遗留格式，并增加回归测试；这说明强校验不仅能发现下载缺失，也能在正式建索引前暴露格式兼容问题。

## 三、实际执行命令

```powershell
conda run -n tls python -m pytest -q

conda run -n tls chronos-repro validate-corpus `
  --data snapshots\crisis\ece08f344cc94933 `
  --dataset crisis `
  --output artifacts\crisis_corpus_validation.json

conda run -n tls python scripts\export_gold_predictions.py `
  ..\chronos_upstream\data\open `
  artifacts\gold_predictions_open_tls

conda run -n tls chronos-repro evaluate-batch `
  --data ..\chronos_upstream\data\open `
  --predictions artifacts\gold_predictions_open_tls `
  --date-only `
  --output artifacts\open_tls_batch_gold_date_smoke.json
```

本轮没有新增 pip 依赖；后续若安装 BM25 或训练库，仍必须显式使用清华源：

```powershell
python -m pip install <package> -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 四、原版 Perl ROUGE 状态

执行 `wsl.exe --status` 和 `wsl.exe -l -v` 后，系统提示尚未安装 Windows Subsystem for Linux/Linux 发行版。当前 Windows 下 `pyrouge` 调用 `.pl` 会产生 WinError 193；`reimpl` 可用于开发回归，但不是论文可比后端。

因此正式实验前必须在 Linux/WSL 中安装 Perl 及原版 ROUGE，使用 `--rouge-backend original` 对同一固定预测目录重跑，并保留输出元数据。安装 WSL 属于系统级变更，本轮未擅自执行。
