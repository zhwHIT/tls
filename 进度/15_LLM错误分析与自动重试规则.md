# LLM 错误分析与自动重试规则

## 1. 更新目的

根据新的运行规则，LLM 调用不再遇到任意错误就立即终止。客户端会先按错误类型判断是否可能恢复：

- 余额不足永远立即停止；
- 瞬时网络、超时、限流、服务端异常和异常响应允许有限重试；
- 缺少密钥、认证失败、请求格式错误等确定性问题，分析为无法通过原样重试解决后立即停止；
- 可恢复错误达到重试上限仍失败时停止，并保留最终错误及实际尝试次数。

## 2. 当前重试参数

| 参数 | 值 | 说明 |
|---|---:|---|
| 初始调用 | 1 次 | 正常模型请求 |
| `max_retries` | 2 次 | 初始调用之外最多再试两次 |
| 最大总尝试数 | 3 次 | 1 次初始调用 + 2 次重试 |
| `retry_backoff_seconds` | 1 秒 | 指数退避基数 |
| 第一次重试前等待 | 1 秒 | `1 × 2^0` |
| 第二次重试前等待 | 2 秒 | `1 × 2^1` |

## 3. 错误决策表

| 错误类型 | 是否重试 | 原因 |
|---|---|---|
| HTTP 402 | 否 | 余额不足，继续调用只会重复失败并可能造成无效操作 |
| 响应包含 `insufficient balance` 等余额标记 | 否 | 即使状态码异常，也按余额不足处理 |
| 缺少 `DEEPSEEK_API_KEY` | 否 | 原样重试不会自动产生密钥 |
| HTTP 400/401/403/404/422 等确定性 4xx | 否 | 通常是请求、认证、权限或资源配置问题，需要修改配置后再运行 |
| HTTP 408/409/425/429 | 是 | 超时、冲突、过早请求或限流通常可能短时恢复 |
| HTTP 5xx | 是 | 服务端或网关异常可能短时恢复 |
| `URLError`、SSL EOF、连接重置、DNS 瞬时错误 | 是 | 传输链路可能恢复，Yemen 实验已证明 SSL EOF 可由后续重试恢复 |
| `TimeoutError` | 是 | 网络或服务响应延迟可能短时恢复 |
| 无效 JSON、解码失败 | 是 | 网关截断或异常响应可能是瞬时问题 |
| 缺少 assistant content 或空内容 | 是 | 模型服务可能返回不完整响应 |

这里的“不可重试”表示在请求参数完全不变时无法合理期待恢复。修正密钥、请求格式、权限或模型配置后，仍可由用户重新启动任务。

## 4. 代码实现

### `src/chronos_repro/llm.py`

新增内容：

- `RetryableLLMError`：表示当前请求可以有限重试；
- `NonRetryableLLMError`：表示分析后原样重试无法解决；
- `_is_retryable_http()`：集中判断可恢复 HTTP 状态码；
- `max_retries=2`：控制最大重试次数；
- `retry_backoff_seconds=1.0`：控制指数退避；
- `_chat_once()`：只执行一次实际 HTTP 请求；
- `chat()`：负责错误分类后的有限重试；
- `ChatResult.attempts`：在成功审计结果中记录实际请求次数。

余额不足抛出 `InsufficientBalanceError`，不会被外层可恢复错误处理捕获，因此可以保证零重试。

### `configs/llm_deepseek_v1.json`

配置文件已明确记录：

- 余额不足不重试；
- 其他错误先分析再判断；
- 最大重试两次；
- 退避基数 1 秒；
- 可重试与不可重试错误范围。

### `README.md`

环境说明后新增 `LLM error handling` 小节，方便复现实验时直接看到运行规则。

## 5. 自动化验证

在原测试基础上新增或加强以下场景：

1. 余额不足 HTTP 402 只调用一次；
2. SSL EOF 第一次失败、第二次成功，结果记录 `attempts=2`；
3. HTTP 401 分析为不可恢复，只调用一次；
4. HTTP 503 连续失败时共尝试三次，然后停止。

执行：

```powershell
conda run -n tls python -m pytest -q chronos_repro\tests
```

结果：`19 passed in 11.07s`。

测试全部使用本地模拟响应，没有消耗 DeepSeek 余额，也没有发送语料。

## 6. 对后续实验的影响

- Yemen 中出现过的 `SSL: UNEXPECTED_EOF_WHILE_READING` 现在会自动进入有限重试；
- 后续实验轨迹会通过 `attempts` 区分首次成功和重试后成功；
- 网络故障不再轻易造成整项主题实验缺失；
- 余额不足仍会立即终止，符合成本保护要求；
- 认证或请求配置问题不会进行无意义的重复调用；
- 达到三次总尝试仍失败时，调用方继续写入 `stopped_llm_error`，便于人工分析后决定是否修改配置或重新运行。
