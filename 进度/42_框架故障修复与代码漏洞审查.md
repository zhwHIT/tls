## 3. 已确认问题与修复

| 问题 | 原有影响 | 本轮处理 |
| --- | --- | --- |
| memory 长度限制只在校验器中 | 模型连续修复仍超长，整条轨迹中断 | 初始 prompt 明示目标不超过 320 字符、硬上限 600；修复请求提供实际长度、硬上限和更短的 300 字符目标 |
| 单个边界说明超长会丢掉可用更新 | 已通过其他验证的更新不能继续使用 | 仅针对重试耗尽后的超长边界说明，使用保守的“边界尚未确认”说明，强制 skeleton_ready=false，再完整验证其他字段 |
| 恢复结果可能污染训练 | 程序生成的文字被误当模型标注 | 保留原始边界文本和恢复原因；标注 deterministic_boundary_fallback_not_training_target，不进入 DeepSeek 来源的 SFT 导出 |
| JSON 解析失败和末尾校验失败审计不完整 | 有返回且消耗 tokens 的响应可能遗漏 | 解析前保存 usage、请求摘要；解析异常携带原响应与审计；终止性标签异常汇入运行审计 |
| 超长上下文按普通标签错误重试 | 修复请求继续增长，不能解决输入过大 | ContextLimitError 直接抛出，不再进入模型标签修复；该超长请求不发 HTTP |
| 陈旧 last_exchange 留在客户端 | 后续失败可能留下上次响应供误接收 | 每次请求入口清空；非 controller 输出也清空待接收记录 |
| teacher 私有字段仅顶层防护不足 | 嵌套字段可能进入部署 controller 输入 | 精简上下文前递归检查私有字段，发现非空内容则拒绝；不会因文档正文出现普通单词而误判 |
| 待核实线索按相同摘要自动关闭 | 不同日期的相似事件误被视为已覆盖 | 自动关闭还需日期兼容；未知日期及原始年/月精度保留兼容处理 |
| gap 状态更新后的落盘时机不足 | 跳过或新发现的 gap 可能没有及时保存 | checkpoint 纳入 gap_memory；空 query 跳过、正常修复周期完成后保存最新 gap 状态 |
| 输出类型转换与描述静默截断 | dict/list 变成字符串；描述后半段丢失 | thought、gap query 必须是字符串；gap 描述超过 180 字符拒绝；prompt 明示该上限 |
| 局部事件视图未保留 conflict | 模型可能看不到事件冲突标记 | 两阶段事件投影保留 conflict 字段 |
| 错误运行自动重启容易被误称续跑 | 缓存重放和真实 checkpoint 恢复混淆 | 已有失败轨迹必须显式使用 --replay-from-start；不清零累计账本；余额停止和已完成运行继续禁止重启 |
| 严格日期评测字段名错误 | 消费不存在的 gold_date_hits 字段 | 从 evaluate_gold_coverage 的 covered_gold_dates 读取，统一输出 gold_date_hits |
| 日期区间端点裁剪可绕过校验 | 从区间截取单日，误当精确事件日期 | 在原始文本中识别 ISO 日期区间，拒绝只来自区间内部的端点引用；保留独立单日陈述 |
| 离线评测只核对主题标签与版本 | 变动后的配置或 gold 可能混入历史结果 | coverage 运行核对原配置哈希、保存配置内容、轨迹版本、快照清单哈希和主题文件哈希；旧版未绑定运行明确标为未检查 |

边界恢复不是截断原始输出，也不凭空补日期或宣称骨架完成。仅当其他字段通过原验证器时才能恢复；仍有其他无效字段则保持失败。恢复步骤不能直接用作 SFT/DPO 正例。

日期检查仍是字面证据一致性检查，不是“事件确实发生于该日”的语义蕴含证明。新增区间裁剪防护目前针对 ISO 区间；其他自然语言表达仍需扩大测试与语义核验。

## 6. 仍需完善的风险

1. **真正断点续跑尚未实现。** 新增的开关只是明确承认从头重放；保存 gap 状态不等于可恢复完整程序计数器、reader、缓存客户端及所有中间变量。修改 prompt 后缓存可能不再命中。
2. **同一输出目录缺少跨进程独占保护。** 并发进程可能竞争账本和输出；目前应串行运行，并避免同时启动同一目录。后续需独占锁和原子恢复协议。
3. **上下文限制目前主要是字符数。** 64,000 字符不是 8k tokens；尚未用最终训练模型 tokenizer 验证每个输入和输出的总长度，也未做目标硬件的显存测试，不能承诺训练不会 OOM。
4. **两阶段效果尚未验证。** Yemen 当前仍是失败的第一阶段轨迹。下一次完整运行必须同时记录阶段结束原因、开放 gap、新增有效日期和最终选择造成的日期损失。
5. **SFT/DPO 样本仍需语义审核。** exact controller 导出标记 training_ready=false；结构正确不等于 query 有效、STOP 合理或事件正确。DPO 正负例必须共享完全相同的 prompt，并有可追溯偏好依据。
6. **用量不等于账单。** 返回响应可审计，未返回响应的真实计费未知；连续修复中又遇到传输/限额异常的审计链还需进一步覆盖。累计 HTTP 账本不能重置。
7. **评测绑定不是完整实验防篡改。** 本次新增检查重点是配置与冻结主题文件；没有新增源代码版本哈希锁定、跨主题全部超参数等价证明、向量逐值审计或签名机制。后续修复运行应使用明确的新代码修订标识，不能无说明地与旧版本合并。
