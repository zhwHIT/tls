## 2. 参考论文的真实配置与本项目设置

### CHRONOS：直接可核实的闭域设置

论文第 5.1 节说明：闭域采用 Elasticsearch，将新闻文章切成约 **500 words** 的片段用于检索；闭域实验包括 Crisis 和 T17。不能将其等同于“每篇只读 700 字符”。来源：[CHRONOS，NAACL 2025，§5.1/§5.4](https://aclanthology.org/2025.findings-naacl.248.pdf)。

本轮借鉴其片段粒度，但不引入新的 Elasticsearch 服务，而是复用已有 BM25＋多语言 Dense 文档召回，在召回文档全文内部进行连续片段选择。**这不是对 CHRONOS 全局片段索引的原样复现。**

### MAS-TLS 与 R2A-TLS：借鉴流程，不臆造超参数

MAS-TLS 对共享候选证据做覆盖与多样性分配，再进行事件审阅和裁决。本项目采用轻量化的段落相关性、文档多样性和弱年份覆盖奖励，不复现其完整多智能体及贝叶斯调度器。来源：[MAS-TLS，ACL 2026，§3](https://aclanthology.org/2026.acl-long.1149.pdf)。

R2A-TLS 的相关性与信息增益过滤、已有文章优先检查、时间点和事件要素补全，支持将“证据已找到但未读充分”与“需要新检索”分开处理。本轮加入未读片段队列与事件候选池。来源：[R2A-TLS，EMNLP 2025，§3](https://aclanthology.org/2025.findings-emnlp.40.pdf)。

以下 Top-K、批大小、轮数均为本项目起始参数，尚未经过效果调优，不声称来自论文：

| 项目 | v6 设置 | 说明 |
| --- | --- | --- |
| 第一层检索 | 现有 BM25＋多语言 MiniLM，1:1 RRF | 不重建已有索引 |
| 每轮文档 Top-K | 40 | 当前融合候选放大倍数 5，因此各通道候选池为 200 |
| 片段长度 | 至多 500 词，同时不超过 3200 字符 | 连续窗口，不拼接远处片段 |
| 片段重叠 | 60 词 | 降低边界处的信息损失 |
| 日期上下文 | 片段前最多 400 字符，另保留标题 | 明确分字段提供，不伪装成正文引文 |
| 每次 SEARCH 选择片段 | 8 | 可以来自本次或历史已召回文档的未读部分 |
| 每个 VERIFY 批次 | 2 个片段，最多 24 个候选 | 不再是一次搜索总共六个候选 |
| 提取分页 | 满批时最多继续到 3 页 | 仍满则标记未完成，留待后续继续 |
| 第一阶段 | 最多 16 轮、至少 6 轮、至少 12 个正式事件后检查 STOP | 粗阶段至少 3 个，仍需边界探索和模型就绪判断 |
| 第二阶段 | 最多 24 个已记录 gap、12 个处理周期 | 保留按尝试次数优先的公平调度 |
| 完整运行安全限制 | 每次启动最多 400 次 HTTP 请求，包含重试 | 不暴露给学生策略；本轮未启动完整 API 运行 |

向量索引仍是每篇一个压缩表示、最大 128 tokens 的既有版本。因此第一层文档漏召回的问题并未完全消失；后续可单独比较全局 passage 索引。当前优先解决的是已经召回的文档没有被充分利用。

## 3. 新的执行流程

```text
Controller：SEARCH / STOP
    ↓ SEARCH
BM25＋Dense 文档召回 → 加入可读取文档集合
    ↓
对新旧未读连续片段做 query 相关性与多样性选择
    ↓
逐批 VERIFY；满批则带已提取列表继续下一页
    ↓
逐批 MERGE（APPEND / UPDATE / DROP）
    ↓
回写真实事件增益、来源增益和未读状态
    ↓
MEMORY_UPDATE：基于合并后的结果更新粗阶段与搜索方向
    ↓
第二阶段 GAP_MEMORY → SEARCH → 分批 VERIFY/MERGE → 更新 gap
    ↓
FINAL_SELECT：从已有事件中全局选材
    ↓
保存候选池、筛选前事件池、最终时间线及独立评测
```

### 3.1 连续片段与来源

每个片段有独立 ID，并保存父文档 ID、正文起止位置、全文 SHA-256、片段 SHA-256。引文和时间证据引用片段 ID，能回查到冻结原文。

片段按连续词窗口生成，并非完整的语义段落划分器。排序使用候选池内词面相关性、文档召回排名、文档分散和片段去冗余；出现较少覆盖年份的片段获得较小加分。年份只是探索提示，不证明该年事件真实发生，更不构成事件结束边界。

选中不等于处理完成。只有 VERIFY 与合并成功、且输出没有撞到分页上限，片段才标为 processed。尚未读取的部分保留在队列，不因整篇文档检索过一次就丢弃。

### 3.2 提取与合并分离

VERIFY 面向小批次原文，输入主题、冻结 keywords、已经提取过的同批事件，不再反复携带整个不断膨胀的时间线。它提取有意义的事实，不在此阶段根据全局时间线过早删除可能的新事件。

MERGE 才处理全局新颖性，接收当前候选以及相关既有事件。相同日期的事件全部保留在合并上下文中，其他事件按词面相关性补充，以减少上下文体积。

v6 不再使用“同一天＋Jaccard≥0.35”作为必须 UPDATE 的硬依据。只有同日文本完全重复的条目被硬拒绝 APPEND；其他语义重复或冲突由模型判断，最终选材再做一次检查。旧版默认阈值行为保留。

已验证但合并失败的候选不会被误认为完成处理；分页的 already_extracted 输入使用独立副本，防止后续结果反向污染之前记录的模型输入。

### 3.3 日期校验保持严格，但允许可审计的年份补全

继续禁止将 `January 2011` 补成 `2011-01-01`。

新增有限的 contextual_year 分支：正文写 `July 27`，标题或给定前文明确支持唯一的 `2013` 时，可以归一化为 `2013-07-27`。模型必须提供同一片段的上下文引文和年份，程序检查引文真实存在、年份唯一、组合后日期一致。

这只是补充缺失年份，不补缺失月份/日期，不自动解释 yesterday 等相对时间，不拿发表元数据替代事实日期。上下文引文存在也不自动证明事件语义关系正确，仍需模型和后续抽查判断。

### 3.4 Memory 改为合并后更新

先提取并合并，再让模型更新粗阶段。避免最后一个必要事件刚加入，程序却把之前的 ready 清空，迫使模型多搜一轮。

完整候选存入程序侧 candidate_pool。工作 memory 保留粗阶段、历史 query、实际增益、待搜和暂缓方向、未读计数，以及最近的日期未确定线索。不会每轮再次要求模型从同一正文重复提取一遍 observations。

新增证据的增益按原文内容哈希归并来源：同一文档的不同片段不被计为多个新文档来源，全文完全相同的副本也不会带来重复来源增益。这仍不等价于独立新闻机构的交叉验证。

### 3.5 最终选材与训练边界

最终模型只能保留或删除已有 event_id，不能借选材重新编造日期或事实。每个删除项必须给出具体理由；不强制固定长度，优先保留不同阶段的相关里程碑。

候选池、筛选前事件池与最终输出分别保存，可检查最终筛选是否降低日期覆盖。FINAL_SELECT 属于通用工具处理，不进入 Controller 的 SFT 样本；程序强制 STOP 同样继续排除。学生输入仍不包含运行预算，Gold 只进入执行后评测。

## 4. 离线验证结果

新旧路径合计 146 项测试通过，新增覆盖：

- 连续片段原文位置一致、文档中间证据可被命中、长无空白文本不丢失。
- 未读队列只有处理成功后才推进。
- 唯一上下文年份可以补全，缺失日期不能凭空补齐。
- 一轮检索通过两个批次提取并合并 10 个事件，突破旧版六候选限制。
- 第二阶段实际使用新 reader 和逐批合并，不回退到旧采样。
- 合并后 memory 已看到本轮新增事件，分页输入没有未来信息泄漏。
- 满页未完成状态及后续继续提取。
- 同日不同事件不被词面阈值强制合并。
- 请求上限包含 HTTP 重试；余额不足第一次异常即终止。
- v6 原文来源审计可发现模型输入文本被改写。

测试中发现并修正了新模块括号错误、相似代码块导致的接入位置误匹配，以及分页输入共享列表的问题；最终以完整测试结果为准。
