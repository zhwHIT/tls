# 目录与文件作用说明

## 一、顶层目录

### `D:\paper\chronos_upstream`

CHRONOS 官方仓库的固定副本。用途是保留原始实现、Open-TLS 数据和上游接口，不应在其中直接开发本项目代码。

重要文件：

- `main.py`：原始 CHRONOS 主流程，包括初始搜索、迭代提问、查询改写、搜索、时间线生成、合并和评测。
- `evaluation.py`：上游 Date-F1 与 Tilse 调用逻辑，是本项目兼容评测的依据。
- `news_keywords.py`：Open-TLS 50 个主题目录名、自然语言查询和序号。
- `data/open/<topic>/timelines.jsonl`：每个 Open-TLS 主题的金时间线。
- `data/question_examples.json`：CHRONOS 迭代自提问的示例池。
- `src/searcher.py`：Bing 或闭域搜索接口。
- `src/reader.py`：网页正文读取接口。
- `src/questioner.py`：根据当前文档提出下一轮问题。
- `src/rewriter.py`：将问题改写为检索查询。
- `src/timeline_generator.py`：从文档生成或合并时间线。
- `src/model.py`：模型 API 调用。

### `D:\paper\news_tls_upstream`

ACL 2020 `news-tls` 官方代码仓库的固定副本。主要作用是提供 T17/Crisis/Entities 的官方数据入口、读取方式、预处理说明和传统 TLS 方法。

重要文件：

- `README.md`：三套数据的 Google Drive 官方入口。
- `news_tls/data.py`：预处理语料的数据结构和读取器。
- `news_tls/datewise.py`：按日期选择和生成摘要的方法。
- `news_tls/clust.py`：聚类式 TLS 方法。
- `news_tls/summarizers.py`：摘要器实现。
- `preprocessing/`：tokenize、HeidelTime、spaCy 三步预处理脚本。
- `resources/datewise/*.pkl`：不同数据集的监督式日期排序器资源。

### `D:\paper\closed_corpora_download`

官方闭域语料的下载暂存区。该目录可能包含未完成下载，不能直接作为正式实验输入。

- `crisis/`：下载完整，但正式实验应读取冻结快照。
- `t17/`：当前不完整。
- `entities/`：当前不完整。

### `D:\paper\chronos_repro`

本阶段自主实现的可复现层，是后续 Search Agent 工程应依赖的主要目录。

### `D:\paper\进度`

本次生成的中文进度与交接文档。只记录事实、命令和状态，不存放训练数据或程序运行产物。

## 二、`chronos_repro` 文件说明

### 项目级文件

#### `pyproject.toml`

Python 项目元数据：

- 项目名 `chronos-repro`；
- Python 要求 `>=3.10`；
- 可选依赖组 `eval` 和 `test`；
- 注册命令行入口 `chronos-repro`；
- 配置 `src` 包发现和 pytest 测试路径。

#### `environment.yml`

记录 Conda 环境名称、Python 版本、清华 conda-forge channel 及核心 pip 依赖。它用于环境说明和重建，但当前实际环境是从本机 base 克隆后安装依赖得到的。

#### `README.md`

面向使用者的英文运行说明，包括环境、Open-TLS 审计、预测评测、闭域冻结和 Windows ROUGE 后端差异。

#### `open_tls_queries.json`

从 CHRONOS `news_keywords.py` 导出的 `{topic_id: query}` 映射。避免审计程序直接导入带外部依赖的上游模块。

### 源代码

#### `src/chronos_repro/__init__.py`

包入口与版本号，目前版本为 `0.1.0`。

#### `src/chronos_repro/data.py`

负责所有时间线输入：

- `parse_date()`：解析日/月/年粒度日期；
- `load_timelines()`：安全读取金时间线 JSONL；
- `load_queries()`：读取主题查询映射；
- `iter_topics()`：遍历数据集下所有主题；
- `load_prediction()`：兼容 CHRONOS 保存对象、字典列表和 Open-TLS 二元组格式。

该文件是后续训练/评测数据层的核心，避免每个实验各自实现不一致的日期解析。

#### `src/chronos_repro/evaluate.py`

负责评测：

- 通用 `_prf()`，能安全处理空预测和空参考；
- `evaluate_dates()`：集合级 Date-P/R/F1；
- `evaluate_tilse()`：封装五类 Timeline-ROUGE，并把所用后端写进输出。

#### `src/chronos_repro/snapshot.py`

负责冻结与验证闭域语料：

- `sha256()`：流式计算大文件哈希；
- `_inventory()`：生成排序后的相对路径、大小、哈希清单；
- `freeze()`：内容寻址复制、staging 校验、清单生成和原子完成；
- `verify()`：重新计算所有文件，检测新增、缺失或内容变化。

#### `src/chronos_repro/cli.py`

命令行入口，提供四个子命令：

| 命令 | 作用 |
|---|---|
| `audit-open-tls` | 校验并统计 Open-TLS |
| `evaluate` | 对单个主题的预测执行日期或完整评测 |
| `freeze` | 生成 T17/Crisis/Entities 内容寻址快照 |
| `verify` | 逐文件复验已有快照 |

### 脚本

#### `scripts/export_open_tls_queries.py`

使用 AST 查找并安全解析 `TARGET_KEYWORDS`，导出 Open-TLS 主题查询。它不会执行上游 Python 文件。

### 测试

#### `tests/test_data.py`

测试日期解析、数据读取、预测格式、空预测 Date-F1，以及便携版 Timeline-ROUGE 金标准回灌。

#### `tests/test_snapshot.py`

测试快照内容寻址、重复冻结幂等性和清单验证。

### 运行产物

#### `artifacts/open_tls_audit.json`

50 个 Open-TLS 主题的逐主题统计，包括查询、参考时间线数、唯一日期数和事件数。

#### `artifacts/gold_date_smoke.json`

只运行 Date-F1 的金标准回灌结果，用于验证日期加载和集合指标。

#### `artifacts/gold_full_smoke.json`

完整评测金标准回灌结果，包含日期指标、`rouge_backend: reimpl` 以及五类 ROUGE-1/2。

#### `artifacts/crisis_snapshot_verify.json`

Crisis 快照最后一次完整性复验输出，与快照内 manifest 内容一致。

### 快照

#### `snapshots/crisis/ece08f344cc94933/`

正式的 Crisis 不可变输入。目录名来自文件清单内容哈希，目录内部有 4 个主题和清单文件。

#### `MANIFEST.sha256.json`

记录：

- schema 版本；
- 数据集名；
- 快照 ID；
- UTC 创建时间；
- 来源说明；
- 文件总数与总字节数；
- 每个文件的相对路径、大小和 SHA-256。

## 三、不应手工维护的文件

以下是安装或运行产生的缓存，不属于核心源码：

- `.pytest_cache/`；
- `__pycache__/`；
- `*.pyc`；
- `src/chronos_repro.egg-info/`。

它们可以重新生成，不应作为数据版本或实验结果依据。
