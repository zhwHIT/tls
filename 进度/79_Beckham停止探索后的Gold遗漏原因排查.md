## 1. 已找到的重要事件被待补证线索调度挡住

退役是最明确的案例：

1. query 1 已召回 18406、18348、18349 三篇 2013-05-16 的退役报道。
2. 实际选中了 18349 的开头 `[0,83)`，模型抽到退役事实，但正文没有日期表达，输出 `time=null / INSUFFICIENT`。候选 ID：`8e40e16555cc-c1`。
3. 线索被保存为 `e5f015fb9e7a7326`，priority=1；停止时位于 **176 条待补证线索中的第 71 位**。
4. 后续 11 次 SEARCH 的可见 `pending_leads` 中，**没有一次出现退役线索**；35 条 query 没有 retirement 查询。

原因落在两个具体实现上：

- [coverage_pipeline.py](../chronos_repro/scripts/coverage_pipeline.py) 将线索按 OPEN 状态、priority、**lead_id 哈希字符串**排序。同优先级内没有等待时间、补证进展或事件多样性排序。
- [batch_memory.py](../chronos_repro/src/chronos_repro/batch_memory.py) 的 `policy_view` 只展示 `lead_queue[:4]`，并且只保留 ID、time、summary、status。源文章 ID、发布日期、原时间表达、具体缺失信息没有提供给搜索策略。

停止时全部 176 条线索的 `attempted_queries` 都为空。这个字段没有在本次执行中形成搜索反馈，不能据其判断某个线索是否已经补证失败。重复、略有措辞变化的未定日摘要占据队列，也没有可靠轮换机制。

**未读文本候选队列与待补证事件线索队列是两套机制。** 本次新增前者，并没有解决后者只暴露哈希排序前四项的问题。

## 2. 银河告别：读到了结果，缺日期的补证却走向 2011

Gold 是 2012-12-01。对应结果文章 **18460**（发布日期 2012-12-02）在 query 5、9、11、15、16、19、22、25、28、32、34 中反复召回；实际进行了 **10 次单片段 VERIFY**。

step-079 已读到 `[146,326)`：Beckham 以连续第二次 MLS Cup 冠军结束美国踢球生涯，Galaxy 击败 Houston。模型明确识别了告别比赛，却因为片段没有明确日期而输出 `INSUFFICIENT`。其余多次读取也反复产生同一告别事件的未定日变体。已检查的文章没有直接提供足以按当前规则确定 2012-12-01 的完整日期锚点；发布日期为次日不能直接视为比赛发生日。

另一个来源 **18474**（2012-11-20）首句已经在 step-057 送入 VERIFY，写着 `on Monday night` 和 `on 1 December`。但该片段的冻结时间注释为空，正文没有年份。现有规则不允许直接用发布日期年份补成发生日期，模型因此拒绝入库。它还是预告，不能未经结果证据确认就当作已经举行的最后一场比赛。

后续本应解决“这场告别比赛的年份及实际举行日期”，查询却发生漂移：

- query 5、9 明确使用 **December 2012**。
- 从 query 16 开始，多次出现 **final/last LA Galaxy ... 2011**；截至停止，共 6 条查询把告别/最后一场和 2011 结合。
- 当时的搜索可见状态同时包含 2011-11-20 的 Galaxy–Houston 决赛事实，以及缺年份的“1 December 最后一场”线索；另有 18588 的 2011 年文章用告别式措辞描述当年的决赛。

这支持“不同年份的决赛/告别报道被搜索策略混淆”的解释，但不是逐 token 的模型内部因果证明。35 条 query 的 `time_filter` 全部为 none，所以**不是硬日期过滤排除了 2012**；年份进入 query 本身就会影响检索排序。

## 3. 联合选句没有形成联合日期证据输入

本轮在线接入保留了 `verification_batch_passages=1`：**254 次 VERIFY 全部只接收一个连续片段**。每次抽取的 `events=[]`；`already_extracted` 只针对相同片段的历史抽取，不提供同文档其他片段的完整证据。`context_before` 为空，所需前文仅靠选句时的局部规则加入。

因此，事件句与日期句即使都被选到，也不保证在同一次 VERIFY 中可见。当前“联合”发生在选择层，没有实现事件与时间证据的联合验证。这是本次在线接入的局限，需要承认，不能将离线选中两类句子直接解释为模型能确定事件日期。

统计也显示证据单位过碎：254 个已验证片段的正文中位数 **148 字符**，46 个不足 80 字符，38 次 VERIFY 没有候选。step-514 甚至单独验证了 `First - team debut` 这一 18 字符标签；后面的日期句没有一同输入。207 个片段没有冻结时间注释，说明仅按年份/月名/星期等词面提示选句，不等于提供了可归一化的事件日期。不过“没有注释”本身不证明没有显式日期。

这不意味着所有遗漏都能靠扩大上下文解决。例如退役报道开头本来就没有日级时间表达；银河结果文章也不能仅凭次日发布日期补全日期。仍需有针对性的补证检索。

## 4. 许多 Gold 支线没有进入有效查询

35 条 query 中，19 条含 Galaxy，11 条含 Real Madrid 或 Mijatovic；这些是可重算、非互斥的词面分类。retirement、100th/hundredth、UNICEF、OBE、Achilles、PSG/Paris、Miami 的显式查询均为 0。

这不能证明广泛查询一定无法召回那些事件，但实际检查到的 OBE、跟腱受伤、百场国家队比赛、PSG 签约、迈阿密计划、UNICEF 基金等直接来源均未在本次召回记录中出现。继续在旧线索里改写同义 query，并不能由“读过更多句子”自动获得这些支线。

## 优先修复顺序（本轮未实施、未继续 API）

1. **补证线索调度**：替换按哈希取前四项；按事件去重、轮换，加入等待时间和尝试记录。搜索输入保留来源、原时间表达、缺失字段及预告/结果状态。
2. **证据组织**：将同一事件的主句与必要日期/年份上下文组织成可一起验证的证据包，保留每段源偏移；同步明确跨片段日期依据契约，不能伪造连续原文。过滤孤立标题和没有有效上下文的极短片段。
3. **定向日期补证**：对“已找到事件但缺完整日期”生成缺口明确的查询；区分 2011 与 2012 两届决赛、预告与实际结果。不能把发布日期一律充当发生日期。
4. **查询多样性与收益反馈**：按事件支线而非字符串判断重复，并区分普通事件数量增长与新的重要事件线索。Gold 只用于离线评测，不进入搜索或筛选。

当前证据支持先修复上述链路。单纯扩大导语占比、增加 top-k 或继续耗费 VERIFY 请求，尚未证明能解决这些问题。
