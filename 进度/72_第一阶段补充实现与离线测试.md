# 第一阶段补充实现与离线测试

本轮按第 71 号方案实施并测试，API 调用 0。新功能由显式 v10 配置启用；本次没有启动付费评测，没有把历史轨迹升级为训练合格数据。

## 已实现流程

1. 从历史父轨迹重放第一阶段，导出有哈希绑定的基线。只取第一阶段实际执行的事件、候选和检索记录，不把第二阶段结果回填为第一阶段。导出记录保留原完整运行账本作历史成本来源，新实验增量单独记账；原账本不清零。
2. 对尚未完成的证据按段落/内容去重，优先续读页数不足的记录；已完成和明确验证失败的记录不进入这条重读队列。重读使用详细抽取，保留已抽取内容，避免反复输出同一批候选。
3. 从冻结主题语料构建事件时间候选池，按固定时间分箱统计相关文档数、未处理证据和已表示日期，选择互不重叠的探索区间。区间分数是探索优先级，不是已确认遗漏。
4. 每个区间的时间线、事实摘要、查询历史和 gap 从空初始化，复用第一阶段查询/VERIFY/MERGE/摘要流程。模型范围与区间取交集；空交集不执行全局搜索。回顾性报道允许进入事件日期匹配的候选池。
5. 检索候选、可见时间标注和最终入库均检查范围；更窄的模型范围在候选筛选与断点恢复中保留。越界候选隔离保存。区间之外的文章上下文日期不作为可入库事件。
6. 区间结果按单候选送入全局合并，保留来源，避免局部 event-001 冲突；先确定性去重，并对高相似但日期不同的候选单独裁决，最后排序、刷新全局摘要并进入第二阶段。全局 MERGE 只提供相关事件窗口，防止整条时间线导致 4K 超限。
7. 第二阶段分别控制每批 query 数、每 gap 批次数和总批次数。示例配置为每批最多 3 条 query、每 gap 最多 3 批、全局 30 批；这些是待评测配置，不是已证明最优参数。

## 状态隔离、断点与日期裁决

当前区间执行为串行。共享累计 API 账本不允许并发写入；workers>1 明确拒绝。本轮没有实现或验收并行 worker 调度，不会把串行测试说成并行安全证明。

每个区间单独保存模型轨迹、候选、摘要、查询批次和处理进度。中断后重建区间 reader，完成未提交批次，再从已完成批次继续；全局按来源游标提交，避免重复合并。子轨迹不混入第一阶段原始轨迹，训练门禁继续保留。

日期裁决读取双方日期证据及对应原文片段，允许 EXISTING、CANDIDATE、DIFFERENT、DEFER。非 DEFER 结果必须有提供证据中的逐字引文；验证失败、原文缺失或输入预算不适合时隔离候选，并标记原事件有冲突，不能直接以“重复”为由抹掉日期分歧。结构检查不证明语义判断一定正确。

## 检查中修复的问题

- 原事件 ID 按现存事件数递增，删除后可能复用编号：改为按当前最大数字编号递增。
- 区间结果汇总可能把整个父时间线送入 MERGE：改为相关事件窗口。
- 断点重建可能丢失模型更窄的检索范围：恢复时重新绑定有效范围及时间标注。
- 仅检查所属大区间不足以执行模型更窄范围：VERIFY 入库同时检查具体日期证据段落的有效范围。
- 抽取缓存可能混淆粗/细抽取及区间：状态显式携带抽取模式和事件范围，并更新缓存协议。
- 日期裁决标签修复失败可能终止整个流程：改为保留证据与待决状态；余额不足/请求预算等全局异常仍向上传递停止。
- 单主题评测原来被“至少两个主题”校验拒绝：现支持单主题；批次先保存生成结果，评测失败时记录 stopped_evaluation_error，避免遗留 running。
- 模拟脚本最初返回空事实摘要，被现有“有事实时不能清空全部摘要”校验正确拒绝；修正模拟响应后通过，没有放松真实摘要约束。
