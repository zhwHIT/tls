# v9.3 三类中断修复与回归验证

日期：2026-09-16。版本：`two-phase-v9.3-validated-local-recovery`。

## 起因

v9.2 的 T17 全量运行已结束，9 个主题均错误中断，未有主题达到 70% 严格日期召回目标。6 个主题因摘要条目超长中断，MJ、Syria 因重复 query 中断，Haiti 因重复 APPEND 中断。旧结果保留在 `artifacts/tisa_v92_all_t17/evaluation_all_topics.json`。

## 修复

### 事实摘要

- 保持每条 6–200 字符的硬约束，prompt 增加建议目标 140 字符，明确不是单词数。
- 修复提示给出具体数组下标、实际字符数和约束；先完整检查来源 ID，避免长度问题掩盖错误引用。
- 重试仍超长时，只选择校验通过的完整条目，并记录未选条目；不截断事实，不删除事件库中的原事件。
- 如果全部条目超长，尝试选择可容纳的完整原事件摘要；仍无可用条目时保留旧摘要和全部事件增量，记录摘要暂缓。同一事件版本不重复请求失败摘要。

### 重复查询

- 模型只看到最近查询，而校验器使用完整历史；现在修复提示会明确列出命中的重复 query/filter 对。
- 重试后仍混有重复项时，仅过滤完全重复项，保留通过完整校验的新查询。
- 重试后全部重复时，第一阶段记录 `invalid_policy_handoff` 并交给 gap 审核；第二阶段仅暂缓当前 gap。均标为执行器恢复，不冒充模型自主停止或完整覆盖，也不作为学生训练标签。

### MERGE 重复追加

- 报错和修复提示提供具体 candidate_id、既有 event_id、日期和摘要，避免模型修改无关候选。
- API 重试仍错误 APPEND 时，只把日期和归一化文本完全相同的重复项改为 DROP，其他候选继续完整校验。
- 原候选及证据保留在恢复审计和候选池中；不会把相似但不同的事件自动合并，也不会声称已完成新证据融合。

另补齐 GAP_STATUS 的 reason 长度提示。现有按批次延迟摘要、事件修订和 4K 输入门禁继续保留。

## 验证结果

- 全套离线测试：**318 passed in 13.20s**。
- 9 个主题的真实失败响应本地回放：**9/9 通过**，无 API 调用。
- 在线组件复测：**9/9 通过，11 次真实 HTTP 请求**，独立累计上限 24。
  - 6 个摘要案例通过新提示完成改写。
  - Syria 查询通过修复；MJ 使用记录在案的重复项过滤，保留新查询。
  - Haiti 完成 MERGE 修复及后续 UPDATE 融合调用。
- 在线组件复测输入最大 **2266 tokens**；输入 11782、输出 1416、合计 13198 tokens。
- `git diff --check` 返回 0。

组件复测先注入一次历史错误输出，再对修复请求调用 API；不是原运行断点续跑，也不是新的完整 T17 评测。摘要在线案例选用原失败响应中的一个超长条目及一个有效条目，并带入其全部对应事件；离线回放覆盖原完整失败响应。

Haiti 小规模端到端集成检查已结束，状态 **ok**：

- 实际 50 次 HTTP 请求；7 个批次、13 条查询、3 次摘要更新，保留 13 个事件。
- 运行覆盖第一阶段、第二阶段、gap 审核、后续搜索与最终选材；1 个 gap 有证据关闭，1 个暂缓。
- 未触发执行器兜底；主轨迹 usage 与全部响应 token 汇总一致。
- 输入最大 **2809 tokens**，学生输入最大 2394、输出最大 108。
- 输入 70862、输出 15970、合计 86832 tokens；加上组件复测，本轮实际共 61 次 HTTP 请求、100030 tokens。
- 第一阶段 4 批、第二阶段 3 个检索周期均触发配置上限，共 2 次 forced STOP，不算自主停止成功。
- 严格日期召回 **4/11（36.36%）**，未达到覆盖目标。该小规模配置检查执行链路，不与完整预算的历史分数直接比较。

组件复测与集成运行的源码指纹一致。新版本没有重新执行全 T17 覆盖评测；旧版 9 个失败结果保持不变。

## 边界

本次验证解决已复现的三类中断，不代表所有错误都能恢复，也不证明完整 T17 的 gold 覆盖率或事件语义正确性。错误来源 ID、非法时间过滤、未知合并目标等仍严格拒绝。4K 结论仅限实际受测输入；未来待训练模型需要按自己的 tokenizer 重新计数。
