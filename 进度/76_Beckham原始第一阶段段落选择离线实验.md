# Beckham 原始第一阶段：段落选择离线实验

日期：2026-09-17。本轮只运行本地对照脚本，API 调用 0。没有修改生产检索代码、原始轨迹、语料、配置或训练门禁。

## 结论

优先读取导语确实能补到此前漏读的退役声明，但本轮两种改法都没有覆盖另外两个已确认存在于召回池中的诊断事件。全部替换为导语会丢失较多原有证据；“一个导语＋一个原段落”损失较少，仍不能直接部署为默认策略。

本轮结论只涉及选段后证据是否可见，没有调用 VERIFY/MERGE，因此不能声称最终 Gold 日期从 0/16 提高到了 1/16。

## 对照范围与预算

- 固定 v9.7 原始第一阶段的 20 批、51 条 query 和每条 query 实际返回的 top-12，排除补充阶段与第二阶段。
- 原选择计划共 102 个段落槽位；实际历史 VERIFY 为 99 次。本次比较的是选择计划，不伪称重放了 102 次模型调用。
- 每条 query 两个段落。每个槽位分别限制：正文字符数、正文加前文字符数、证据文本投影 token 数不超过原槽位，必要时在词边界缩短替代段落。
- 使用现有官方 tokenizer 文件。token 投影包含 id、document_id、title、publication_date、text、context_before；不含重新生成的时间注释、动态 memory 和系统提示。因此这是证据文本预算，不是完整 VERIFY 输入的 3800/4096 预检，也不是 API 费用。
- 查询序列固定，即使替代段落会改变后续模型决策，也不重新生成 query；结果是固定历史查询下的离线干预，不是完整策略闭环效果。

## 三种策略

|策略|具体操作|
|---|---|
|原记录|直接使用保存的 passage_ids 还原原文，没有用当前 reader 冒充历史实现|
|原文章全部改导语|保持两个原选中文档，各取首段；同段重复或无法满足预算时保留原槽位|
|top-12 导语＋原段落|在本条原 top-12 中优先选择尚未读过导语的文章，再以 0.7×query 词项 IDF 覆盖＋0.3×倒数排名排序；替换第一槽，保留第二槽，重复时交换槽位|

分段参数保持 180 words、1200 chars、30 words overlap。第三种策略只保存“已选过哪些导语”的选择状态，不模拟 VERIFY 是否成功。原选择中的历史复用文档依旧允许保留，未额外检索新文档。

策略评分不读取 Gold 或评测标注。评测集是已经分析过的 Beckham 诊断材料，非盲测；仅一次固定策略比较，未按本轮结果反复调权。

## 评测标注

评估三个已经确认召回、但原选段漏读的事件：

1. 2013-05-16 退役：18406、18348、18349 的正文明确声明。
2. 2008-03-26 第 100 场国家队比赛：19367，2008-03-27 发布，首句包含 last night。
3. 2007-07-21 银河首秀：19197，2007-07-22 发布，正文包含 debut 和 Saturday night。

另将 18446 的 PSG 签约预告与 18462 的银河最后一场比赛预告单列，不计为已经发生的 Gold 事件。标注使用原文逐字短语及字符偏移；事件描述与相对日期证据分开统计。

这三个事件是针对性诊断子集，不是完整 Gold qrels。报告 1/3 只表示三组已标注事件中一组证据进入输入范围，不是完整 16 日期召回，也不证明能提取到正确日期。未命中标注不等于没有其他语义等价证据。

同时检查原历史 45 条 SUPPORTED 候选的日期证据引文是否仍在所选正文或连续前文中。45 条均可在冻结原文精确定位；它们含重复候选和后来被 DROP 的候选，因此这个指标是引文保留，不是 45 个正确事件的召回。

所有方法都没有超过逐槽位的原预算上限；不是强行填满到相同消耗。第三种方法少用 6.90% 的证据投影 token，但不能据此宣称节省同等比例费用或总体性价比提升。

## 具体变化

### 退役声明被补到

query 2：`David Beckham biography milestones clubs and England`。

原两个槽位为 18853 的 1567—2452、20162 的 0—1010。第三种方法改为 **18406 的 0—884**，保留 20162 的原段落。18406 第一段的退役声明因此进入输入；不再只读其 2822—3771 的红牌和离队回顾。

全部改导语策略也在 query 3、4、43 覆盖该声明，但后两次是重复覆盖同一事件，不能按三次收益计算。

### 另外两个事件仍漏读

19367 只在 query 2 出现，排第 2；该次导语槽选中了第 1 名的 18406。19197 只在 query 35 出现，排第 7，没有赢得导语槽。说明每条 query 只给一个导语机会，且只从本条结果中选择，会让仅出现一次的重要候选继续遗漏。

### 新增证据伴随旧证据损失

第三种方法丢失 6 条历史候选引文，涉及 2009-06-10 英格兰比赛、2007-05-25 和 2007-05-23 两场比赛、2002-06-05 关于红牌的表态、2007-08-23 银河比赛、2007-08-29 膝伤。精确候选 ID 见 JSON；全部改导语丢失 13 条。

这些历史候选中有预告、日期质量疑点，因此不能把“损失 6 条引文”直接解释成净损失 6 个正确事实。但已有证据损失足以否定“补导语一定无损”的主张。

## 下一轮建议

1. 保留预算内的“待阅读文章队列”，让只出现在某一次 top-12 的文档不会在下一条 query 消失；按主题相关性、是否已有主事件覆盖及重复度调度，不按 Gold 排序。
2. 比较“完整导语替换”与“较短主事件句＋原相关证据段”的预算分配，保持连续原文和来源边界；不能为新增一句主事件而不加区分地丢掉原证据。
3. 在扩展的事件证据标注上量化新增与丢失，再进行真实 VERIFY。此次未执行这三项，也未证明最终日期覆盖改善。
