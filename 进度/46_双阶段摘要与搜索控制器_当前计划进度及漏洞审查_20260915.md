## 2. 已确认的目标架构

```text
冻结语料＋混合检索＋完整外部事件库
                    │
       DeepSeek 摘要更新模块（不训练）
                    │
       任务＋阶段摘要＋必要事件＋新线索
                    │
        Qwen 约 7B 搜索控制器（SFT / DPO）
                    │
          SEARCH(query, time_filter) / STOP
                    │
           检索 → VERIFY → MERGE
                    │
            写入外部事实库并更新摘要
```

- DeepSeek 使用固定 prompt 与 few-shot 更新摘要，不训练摘要模型。
- 搜索控制器重点学习：搜什么、如何改写查询、何时调整时间范围、何时停止。
- VERIFY、MERGE、UPDATE 暂时由固定流程及通用模型承担，不要求学生同时学习所有动作。
- 第一阶段构建全局粗骨架；第二阶段初始化 gap，并对具体缺口进行局部修复。
- gold 用于离线评价、训练主题的遗漏诊断和候选偏好评价，不进入部署时的策略输入。
- 完整事件、证据、原始查询和动作日志保存在外部库，不因摘要压缩而删除。
- 具体 Qwen 检查点、tokenizer、训练实现和显卡尚需确认；“约 7B”不是一个可直接加载的模型标识。

## 3. 第一阶段 memory 的正式要求

### 3.1 必须保留的四类信息

1. 已发现的阶段及大致时间范围。
2. 阶段内的主要经过。
3. 搜过哪些方向、发现了什么。
4. 哪些方向尚未尝试，哪些已经搜索但证据不足。

memory 是检索工作的状态摘要，不是最终时间线，不应只复述已经合并的精确日期事件。

### 3.2 粗粒度骨架与正式事件分离

| 信息类型 | 能否进入骨架 memory | 能否直接进入精确日期时间线 |
|---|---|---|
| 文档支持某事件发生于某年 | 可以，标记 year 精度 | 不可以 |
| 文档支持某事件发生于某年某月 | 可以，标记 month 精度 | 不可以 |
| 文档支持大致时期但边界不确定 | 可以，标记范围与不确定性 | 不可以 |
| 文档支持具体年月日及事件 | 可以 | 仍须通过日期与事件证据校验 |
| 模型猜测的历史阶段 | 只能记录为待探索方向 | 不可以 |

不得把 `1996` 补成 `1996-01-01`、把 `1996-06` 补成 `1996-06-01`，再当作真实事件日期。搜索所需的范围边界与事件事实日期必须是不同字段。

建议骨架节点至少包含：稳定节点 ID、阶段概述、时间值及精度、证据引用、未确定信息。只知道年份并不表示整段历史未知。

### 3.3 搜索方向状态

| 状态 | 含义 | 禁止的误用 |
|---|---|---|
| UNTRIED | 该方向尚未实际检索 | 不能只因摘要没有记录就判定未搜索 |
| PROBED_UNRESOLVED | 已经搜索，但目标信息尚未得到支持 | 不能在下轮改回 UNTRIED |
| SUPPORTED | 已找到支持该方向目标的证据 | 不能仅因新增了不相关事件就标记完成 |
| DEFERRED | 目前缺少可行搜索线索，暂缓 | 不等于事实不存在，也不等于整个任务完成 |

每个方向保留：方向 ID、检索目标、已尝试 query 及时间参数、结果摘要、支持节点或文档引用、尚未解决的原因。

查询是否真正执行、执行次数及实际过滤参数，以执行器日志为准。摘要模型可以归纳，但不得凭空修改这些记录。

### 3.4 摘要更新来源

第一阶段摘要更新不应只读取正式事件列表，应同时读取：

- 旧摘要；
- 新检索材料中有引用支持的粗时间线索；
- VERIFY 结果及其不确定性；
- MERGE 后的事件增量；
- 本轮查询目标、实际参数及执行结果。

某线索不足以通过日级 VERIFY，不代表它完全没有骨架价值。应区分“年份级事实有支持”和“精确日期不足”，而不是统一抹去。

## 4. 第一阶段 SEARCH 与 time_filter 规范

### 4.1 所有第一阶段策略输出都显式包含 time_filter

SEARCH 时由模型自主选择参数；不限定时间也必须输出 `mode: none`，不能省略字段。为保持统一输出格式，STOP 时固定输出 none，并将起止日期设为 null。

```json
{
  "reason": "一句简短且可检查的执行原因",
  "action": "SEARCH",
  "query": "具体检索词",
  "time_filter": {
    "mode": "none",
    "start": null,
    "end": null
  }
}
```

### 4.2 模式含义

| mode | 契约 | 典型使用方式 |
|---|---|---|
| none | 不按文章发布日期限制检索 | 初始发现阶段、找回顾性报道、探索未知时期 |
| soft | 优先范围内文章，保留范围外候选机会 | 围绕已知阶段发散、查阶段转折、修复 gap |
| hard | 排除范围外文章 | 有明确理由严格限定文章发表时间时使用 |

此处过滤依据是文章发布日期，而不是事件发生日期。历史事件可能由多年后的文章回顾。因此，搜索某年事件通常先将年份写入 query，不能直接据此强制 hard 过滤发表日期。

第一阶段默认使用 none 或 soft。第二阶段通常优先 soft。范围过窄且无收益时，应考虑改写 query、放宽范围或切换 none，而不是重复原参数。

### 4.3 参数验证与可追溯性

- SEARCH 的 query 必须是非空字符串。
- STOP 的 query 固定为空字符串，time_filter 固定为 none/null/null。
- none 模式要求 start/end 均为 null。
- 本版拟议契约中 soft/hard 要求两个完整 ISO 日期，且 start 不晚于 end；如将来需要开放区间，应显式升级契约。
- 用户指定的事件时间范围，不得自动解释成文章发布时间的 hard 限制。
- 执行器不得无记录地改写模型参数；应同时保存 requested_filter 与 executed_filter。
- 日期边界是否包含当天、时区、缺失发布日期处理，应在检索适配层写明并有测试。
- 第二阶段历史协议 `SEARCH("")` 仅表示跳过当前 gap，不执行真实检索；不得与第一阶段非空 query 规范混淆。

## 5. 第一阶段策略 prompt 草案

以下为待实现的契约草案，不代表当前代码已采用。工具与输入输出规范应写入稳定 system prompt；few-shot 也计入学生输入长度。

```text
你是闭域时间线任务的第一阶段搜索控制器。
目标是发现语料支持的主要阶段、粗时间范围及主要经过，形成大致骨架。
你不直接生成正式事件，不修改证据，不使用参考答案。

你会收到：
1. task：公开主题与任务要求。
2. phase：SKELETON_EXPLORATION。
3. memory：已知阶段、主要经过、搜索方向及其执行状态。
4. events：按时间排序的必要事件视图；未展示不代表外部库不存在。
5. latest_observation：本轮新增线索、证据引用和查询结果摘要。

可用动作：
SEARCH(query, time_filter)：查询冻结语料，随后环境执行证据核验、合并与摘要更新。
STOP：结束第一阶段并转入 gap 分析，不代表整条时间线已经生成完毕。

时间工具规范：
time_filter 作用于文章发布日期，不是事件发生日期。
none：不限制发布日期，start/end 为 null。
soft：优先 start/end 范围内文章，但允许范围外候选。
hard：排除范围外文章，只有明确需要严格限制发表时间时使用。
soft/hard 的 start/end 为 YYYY-MM-DD，start <= end。
寻找早期事件时应考虑后来的回顾报道，不要机械限定早期文章发布日期。

决策要求：
依据关键词、已发现阶段、相关实体和新线索自主发散查询。
年份/月级节点可以支持骨架，不要因为没有精确日期就判定该阶段完全未知。
区分尚未搜索、搜索后未解决、有证据支持与暂缓的方向。
不要重复已经无收益的同一查询与时间参数组合。
新增事件只有真正回应当前方向目标时，才表示该方向取得进展。
若仍有合理、可检索的阶段线索，应继续 SEARCH；不得只因事件条数增加就 STOP。
reason 仅输出一句简短决策依据，不输出长篇思考过程。

输出规范：
仅输出一个 JSON 对象，字段为 reason、action、query、time_filter。
action 仅允许 SEARCH 或 STOP。
SEARCH 的 query 非空，time_filter 必须显式给出。
STOP 的 query 为 ""，time_filter 为 {"mode":"none","start":null,"end":null}。
不得输出 gold、奖励分数、预算、完整时间线或完整 memory。
```

few-shot 应采用虚构主题或合规训练主题，至少演示：

1. 初始空骨架：广泛查询，time_filter=none。
2. 只有年份级阶段：承认阶段已被发现，改查相关主体或相邻发展，不强行寻找不存在的日级细节。
3. 已试过一个方向但证据不足：改写关键词，或扩大 soft 范围，不能重复声明“尚未搜索”。
4. 查询历史事件：年份进入 query，但允许后期回顾文章，time_filter=none。
5. 骨架相对完整且主要方向已处理：STOP，将局部细节交给第二阶段。

不能把特定 dev 主题的隐藏事件安排写成 task_description 或 few-shot 答案。

## 6. 独立 DeepSeek 摘要模块规范

### 6.1 责任与 prompt 要点

摘要模块负责压缩和整理状态，不替搜索策略预先决定所有查询。它不看 gold，不需要生成长篇反思，不重新生成全部事件库。

摘要 prompt 必须要求：

- 仅使用提供的旧状态、新材料及执行日志；
- 保留已发现阶段和粗日期精度，不补造具体日期；
- 保留主要经过，而非只列日期与人名；
- 逐方向记录查询目标是否得到回应；
- 保留失败搜索的有效结论，避免下轮重复；
- 对新发现线索允许新增方向；
- 保留证据引用与不确定性，区分计划、传闻和已经发生的事实；
- 不把“当前输入未展示”推断为“语料或事件库不存在”；
- 只输出指定摘要结构，不输出正式时间线或参考答案。

few-shot 应覆盖：年份/月级事实、重复搜索无收益、阶段时间范围扩展、同一文档中的回顾事件、冲突证据及待定 gap。正式上线前冻结 prompt 版本并记录每次调用所用版本。

### 6.2 两阶段不同摘要

第一阶段是全局阶段摘要，建议约 500–1,000 个目标 tokenizer tokens；第二阶段是当前 gap 及局部证据摘要，建议约 250–600 tokens。这些只是初始工程目标，不能为了达标删除不可恢复的关键信息。

全局 gap 初始化可由固定模块分阶段或分窗口分析事件库，再合并去重；每次局部修复后，应检查受影响邻接事件是否产生新 gap，而不是重复输入全部历史。

## 7. 学生数据与长度验收

### 7.1 SFT

- 单步输入包含完整 system prompt、few-shot、工具规范、状态、消息模板开销。
- 输入最多 3,584 tokens，输出含结束标记最多 512 tokens，总序列最多 4,096 tokens。
- 常用动作输出目标为 80–256 tokens，不要求填满输出空间。
- 用最终选定的 Qwen tokenizer 计数，不使用字符数或 DeepSeek token 数代替。
- 超长样本先重新构建状态视图；禁止直接截掉 JSON、关键证据或当前 gap 后继续训练。
- 只对学生应生成的决策输出计算训练损失；工具反馈和固定模块输出不作为学生预测目标。

### 7.2 DPO

- 每对样本使用完全相同的压缩输入，chosen/rejected 为不同决策。
- 两个候选均须满足输出上限 512 tokens。
- DPO 两个分支分别为 `prompt + chosen` 与 `prompt + rejected`，各自不得超过 4096 tokens；不将两个回答顺序拼接成一条序列。两个分支均须验证，计算成本仍高于单个 SFT 样本。（2026-09-15 实施复核纠正。）
- 优先构造 query 改写、时间范围调整、SEARCH/STOP 的偏好样本。
- 用相同语料和固定处理模块实际执行分支，保存检索增益与证据评价。
- 不强行配对差异不明确的候选，不只因命中更多日期就判定更优。

### 7.3 数据分割与真实性

先按主题划分训练、验证和测试，再拆分轨迹。来自同一主题的步骤、摘要版本、分支候选保持在同一分区。少数主题的许多步骤不能视为许多独立主题，也不能据此断言泛化数据已经足够。

教师必须在学生真正会看到的压缩输入上生成动作，而不是先读完整历史得到答案、再给学生删除关键依据的输入。摘要只能使用当前时点之前的证据。

gold 辅助修复只能用于训练分区；需要检查建议 query 是否依赖学生不可见的隐藏信息。已经反复诊断的 dev 主题不能重新声称是未见测试主题。

## 10. 漏洞与优先级

### P0：必须先处理的契约与事实问题

1. **粗时间线索被日级校验吞掉。** 历史已观察：年份级人物经历可能因不能精确到日而被统一视为不足。修复方向：分离骨架节点、待定候选、正式事件三层，不降低正式日期校验。
2. **搜索方向状态失真。** 历史已观察：已尝试方向仍被摘要描述为未探索；无关新增事件被当成当前方向收益。修复方向：稳定方向 ID、日志驱动的尝试状态、面向意图的证据支持判断。
3. **日期解释有语义漏洞。** 历史已观察 Bowie 相对星期日期与出生日期不一致。修复方向：检查过去/未来方向、文章时间和事件语境；不确定则保留不确定，不按 gold 强改日期。
4. **第一阶段 time_filter 契约尚未按新要求逐项验收。** 待检查 prompt、解析器、执行参数与轨迹导出是否一致，none 是否显式输出，STOP 是否统一格式。
5. **4K 目标缺少端到端 tokenizer 门禁。** 不能只检查状态 JSON，不检查 prompt、few-shot、工具定义及聊天模板。

### P1：影响多轮效果与数据质量

6. **gap 过于宽泛且可能不可回答。** 应具体到可检索信息与证据验收条件，允许暂缓，不把所有叙事不连贯都判成必须补齐的事实。
7. **停止行为主要由执行器兜底。** 模型 STOP、阶段切换、轮数终止、余额不足和额度终止必须分别记录；强制终止不能直接作为 STOP 正例。
8. **跨日合并可能损失有效事件或混淆日期。** 区分公告日、计划发生日和实际发生日；不能以保住 gold 命中为由无条件 APPEND。
9. **新摘要可能制造假缺口。** 省略事件不等于事件不存在；gap 模块需要外部事件库支持。
10. **训练样本可能包含不可见依据。** gold 引导 query、事后摘要和完整历史教师动作都需单独审查。
11. **新检索词发散可能偏离语料故事范围。** 从实际语料线索逐步识别主题范围，不能对人物主题无限扩成整个人生，也不能注入特定测试主题答案。

### P2：效率、复现与实验解释

12. **真正的断点续跑仍有不足。** 历史主要依赖源代码绑定的缓存回放；prompt 变化会影响复用。应显式记录恢复边界，不重置调用账本。
13. **评测分母与语料可支持性不同。** 某些 gold 日期未被当前解析或扫描发现，不足以证明不在语料中；不得据此删减 gold 分母。
14. **固定摘要模块也会引入成本与错误。** 控制器与摘要调用分别统计，不能只比较学生输入长度而忽略系统总成本。
15. **缺少公平消融。** 不同请求额度、不同代码版本和不同检索配置下的召回差异，不能直接归因于 memory 模块。

## 12. API 授权与验收边界

本轮没有新 API 调用授权动作，也没有执行 API 请求。下一轮需要在线验证时，应明确发送的主题、字段、片段限制与调用额度；在授权范围内执行，余额不足立即停止。

上线前至少满足：

- 第一阶段 SEARCH 始终输出合法 time_filter；
- 年/月级骨架线索被保留，但没有伪造日级事件；
- 搜索状态不退回、不凭无关收益标记完成；
- 摘要忠实于当时证据和日志；
- 学生输入按目标 tokenizer 严格验收，输出有界；
- 多主题评测保留失败运行，不通过删主题或删 gold 日期改善分数；
- 停止原因与训练可用性清楚区分。
