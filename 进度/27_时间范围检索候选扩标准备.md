## 1. 动机

上一阶段在 29 个 dev 事件上完成了 none、soft、hard 日期模式消融。soft 的已标注 Recall@20 和 nDCG@20 高于 none，但 soft 有 144/580 条返回未进入现有 qrel；hard 有 231/397 条未标注。若直接把未知文档当作不相关，结果只能作为开发信号，不能作为最终检索结论。

本阶段构造统一补充池，只标注 soft/hard 相对现有 2,532 条 qrel 新出现的 event-document 关系，然后重新计算公平指标。准备过程完全在本地执行，不调用 DeepSeek。

## 2. 候选构造方式

输入包括：

- artifacts/temporal_filter_qrel_ablation_v1.json：29 个事件在三种日期模式下的排名；
- artifacts/agent_query_qrel_expansion_v1/qrels.merged.jsonl：当前 2,532 条 qrel；
- 三个冻结 BM25 索引：用于按文档 ID 读取标题、发布日期和受限正文。

处理流程：

1. 每个事件分别收集 soft 与 hard 的文档 ID；
2. 对相同事件、相同文档跨模式去重；
3. 删除现有 qrel 已覆盖的 event-document 对；
4. 只保留该文档实际由哪些事件查询检出的关系；
5. 按 topic 内文档去重，一篇文档可以判断多个实际关联事件；
6. 从冻结索引读取每篇最多 700 字符正文；
7. 生成与现有多事件标注器兼容的 candidates.json；
8. 运行不带 --execute 的 dry-run，确认不会发起 API 请求。

## 3. 重要优化

第一版沿用真实 Agent query 扩标策略，把每篇新文档与同主题全部抽样事件进行判断，产生 469 篇、3,913 个 event-document 对、60 批。这对无法映射具体事件的自由 Agent query 是合理的，但时间消融中的每个 query 已与一个 evaluator event 一一对应。

因此已改为事件特定 pooling：文档只对实际检出它的事件进行判断。最终规模降为 221 篇、250 个 event-document 对、28 批，减少 93.6% 的判断量，同时不损失本次消融所需标签。
