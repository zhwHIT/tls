## 一、工作区检查

## 二、下载并固定 CHRONOS

执行：

```powershell

```

得到 commit：

```text

```

检查了：

- `main.py`：主题遍历、生成、合并和评测调用；
- `evaluation.py`：Date-F1 与 Tilse Timeline-ROUGE；

- `data/open/*/timelines.jsonl`：金时间线。

识别出的上游问题：

1. 使用 `eval()` 解析数据；
2. 空预测时 Date precision 可能除零；
3. 运行在线 CHRONOS 需要模型 API、Bing Search API 和可选 Jina Reader key；
4. 原版评测依赖 Perl ROUGE，在 Windows 不可直接运行。

首次只使用 Python 标准库运行 Open-TLS 审计，不依赖 CHRONOS 的在线 API。

## 四、Open-TLS 查询导出与审计

为了不导入 CHRONOS 中可能连带加载 API 依赖的模块，`export_open_tls_queries.py` 使用 Python AST 安全读取 `TARGET_KEYWORDS` 常量并导出 JSON。

操作：

```powershell
$env:PYTHONPATH = "src"
python scripts\export_open_tls_queries.py `
  ..\chronos_upstream\news_keywords.py `
  open_tls_queries.json

python -m chronos_repro.cli audit-open-tls `
  --data ..\chronos_upstream\data\open `
  --queries open_tls_queries.json `
  --output artifacts\open_tls_audit.json
```

结果为 50 个主题、1,130 个唯一日期、2,070 条事件，无读取失败。

## 八、Timeline-ROUGE Windows 适配

安装 Tilse 后首次执行完整评测，产生：

```text
OSError: [WinError 193] %1 不是有效的 Win32 应用程序
```

原因是 `pyrouge` 试图直接启动 `ROUGE-1.5.5.pl`。检查本机后没有找到 Perl。因此没有篡改第三方包，而是在项目层增加：

```text
--rouge-backend original
--rouge-backend reimpl
```

开发期 Windows 使用 `reimpl`，最终论文对比应使用 Linux/WSL 的 `original`。

完整冒烟命令：

```powershell
conda run -n tls chronos-repro evaluate `
  --data ..\chronos_upstream\data\open `
  --topic Islamic_State_2019.10.27 `
  --prediction ..\chronos_upstream\data\open\Islamic_State_2019.10.27\timelines.jsonl `
  --rouge-backend reimpl `
  --output artifacts\gold_full_smoke.json
```

全部指标返回 1.0。
