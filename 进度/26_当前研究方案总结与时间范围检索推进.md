## 1. 研究目标与当前主线

本课题面向时间线摘要生成（TLS），目标不是单纯训练一个端到端摘要模型，而是构建一个能够反复执行 SEARCH、VERIFY、MERGE、STOP 的 Search Agent。当前最可行的毕业设计主线是：

1. 使用冻结闭域语料和固定混合检索器，保证实验可复现；
2. 使用两阶段 Memory 管理检索过程；
3. 训练专用 Controller 学习查询生成、SEARCH/STOP、阶段切换和 Memory 更新；
4. VERIFY 与 MERGE 先交给冻结通用模型，并用程序规则校验；
5. 使用 SFT 学习正确轨迹格式和基础策略，再使用同状态 DPO 优化局部动作选择；
6. 用最终时间线质量、证据忠实性、检索覆盖和调用成本联合评测。

核心研究问题是：在相同检索器和执行器下，两阶段结构化 Memory 与局部偏好优化，能否提高新事件发现、关键 gap 修复和停止时机判断的质量。

## 2. 两阶段 Agent 流程

### 2.1 SKELETON_EXPLORATION

初始时间线为空，coverage memory 记录已覆盖的时间段、关键锚点、历史查询及新增事件。Controller 先输出简短 thought，再选择 SEARCH 或 STOP。每次非空查询依次执行：

SEARCH → 多篇候选 → VERIFY → MERGE → 更新时间线与 coverage memory

这一阶段不读取 Gold，目的是在真实运行条件下形成事件骨架。它不追求一次查全，而是关注每轮是否发现新的时间段或关键事件。

### 2.2 GAP_REFINEMENT

进入第二阶段时执行 GAP_MEMORY：分析当前按时间排序的事件序列，识别时间断点、因果断点、关键因素缺失和证据冲突。对每个 active gap 输出简短 thought，并执行一次 SEARCH；空 query 表示该 gap 无需继续检索。

非空查询仍执行 VERIFY 与 MERGE。MERGE 只允许：

- APPEND：证据支持新事件，追加到时间线；
- UPDATE：与已有事件重合或互补，调用独立模型融合两个结果；
- DROP：无关、重复、证据不足或冲突无法解决。

每轮 MERGE 后必须重新分析 gap，因为新增事件可能关闭旧 gap，也可能暴露新的因果或时间缺口。

### 2.3 Gold 的使用边界

Gold 是私有教师和离线评价信号，不进入学生模型输入，也不进入运行时检索器。

- 第一阶段：DeepSeek 在冻结语料上真实执行，不使用 Gold。
- 第二阶段训练标注：教师可比较第一阶段时间线与 train Gold，定位遗漏并选择高价值搜索方向。
- 学生可见标签：只保留当前事件、Memory、简短 thought、action 与真实工具 observation，不出现“Gold”“参考答案”等泄漏词。
- dev/test：Gold 只用于评测，不用于查询生成、融合权重选择或标注。

### 3.2 检索索引

当前生产检索器由以下部分组成：

- SQLite FTS5/BM25：索引全文，保留实体词、日期词和精确匹配优势；
- paraphrase-multilingual-MiniLM-L12-v2：支持跨语言与同义表达；
- ONNX 动态 INT8：CPU 推理；
- 每篇文档一个 384 维 float16 向量，内容抽取正文开头、中部和结尾；
- 按 topic 分片、原子发布、可断点续建；
- 默认 1:1 weighted RRF，之后做正文哈希去重和轻度同日多样化；
- 偏 BM25 的 quota fusion 保留为排序质量消融，不替换默认配置。

三套 Dense 集合已经覆盖全部 72,959 篇文章，向量与 BM25 文档逐 topic 对齐。热查询约 0.03--0.57 秒。

## 5. 本轮新增：时间范围检索

### 5.1 为什么要增加

此前索引保存并返回 timestamp，但没有 date_from/date_to 过滤。查询中的年份只是普通词项，temporal diversity 也只降低同日重复，不能保证返回某个时间窗口。对 GAP_REFINEMENT 而言，这会让局部 gap 查询被主题中其他年份的高频报道淹没。

### 5.2 三种模式

| 模式 | 行为 | 适用场景 |
|---|---|---|
| none | 完全保持旧检索行为 | 第一阶段全局骨架、历史实验复现 |
| soft | 区间内证据优先，区间外证据降权但保留 | 第二阶段 gap 修复的推荐默认值 |
| hard | 在各模态 top-k 截断前排除区间外文档 | 明确局部时间窗口、严格消融 |

边界采用 YYYY-MM-DD、左右均包含。必须强调：索引中的日期是文档发布日期，不一定等于文章所述事件的发生日。因此不能全局强制 hard，否则会漏掉事后回顾和迟发报道。

### 5.3 代码改动

- src/chronos_repro/temporal_filter.py：统一日期参数校验、范围判断、soft 重排和审计元数据；
- src/chronos_repro/retrieval.py：BM25 在 SQL 候选截断前执行 hard；Hybrid 将配置传给两个模态；
- src/chronos_repro/dense_retrieval.py：Dense 在向量打分前裁剪 hard 候选，soft 模式扩大候选池后重排；
- src/chronos_repro/cli.py：search 与 trace-search 新增日期边界、模式和软惩罚参数；
- src/chronos_repro/trajectory.py：每轮 SEARCH action 保存日期配置，旧轨迹缺省按 none 重放；
- tests：新增 BM25、Dense、Hybrid、soft 语义、参数校验和轨迹重放测试。

默认 mode=none，因此已有脚本和历史轨迹保持兼容。

新增 scripts/evaluate_temporal_filter_qrels.py，只读取本地冻结索引、Gold evaluator query 和现有 qrel，不调用 LLM。它会记录 Recall、nDCG、MRR、区间命中数、judged/unjudged 数量，并校验 none 是否复现历史缓存。

在 29 个 dev 事件、±14 天窗口、soft_penalty=0.5 上得到：

| 模式 | MRR | Recall@20 | nDCG@20 | 区间内结果 | 已标注结果 |
|---|---:|---:|---:|---:|---:|
| none | 0.5026 | 0.8472 | 0.6685 | 110/580 | 580/580 |
| soft | 0.6529 | 0.8761 | 0.7758 | 294/580 | 436/580 |
| hard | 0.6494 | 0.7221 | 0.6846 | 397/397 | 166/397 |

但该对比尚不具备最终统计效力：原 qrel 池主要来自 none 检索与已有 Agent query，soft 有 144 条、hard 有 231 条返回结果未标注。正式结论前应补标这些新增候选，或采用统一的深池重新构造 qrel。完整报告位于 chronos_repro/artifacts/temporal_filter_qrel_ablation_v1.json。

## 6. SFT、DPO 与奖励构造

### 6.1 SFT 数据

每个 Controller 样本只包含当前可观察状态：

- phase；
- 按时间排序的 events；
- coverage memory 或 gap memory；
- active gap；
- 历史 query 与工具 observation；
- valid actions；
- 简短 thought；
- action，包括 query、可选时间范围和检索模式。

不把 budget 放入模型输入。预算由执行器作为安全上限维护，避免模型把剩余轮数当成停止捷径。

### 6.2 同状态 DPO

推荐构造四类局部偏好：

1. Query：新增事件或直接证据更多的查询优于错年代、过窄、重复查询；
2. SEARCH/STOP：开放 gap 且仍有可达证据时 SEARCH 优于 STOP；gap 已关闭且连续低增益时反向；
3. 时间模式：在同一 query 下比较 none、soft、hard，按新事件覆盖、Grade 2 增益和漏证据风险排序；
4. Memory update：能明确已覆盖范围、未解决 gap 和历史 query 的紧凑更新优于模糊或遗忘更新。

VERIFY 与 MERGE 暂不作为 Controller 的主要 DPO 目标，可由通用模型执行并使用程序校验；后续只做“通用执行器 vs 专门 SFT”消融。

### 6.3 边际奖励

建议奖励按优先级组合：

新 Gold 事件覆盖 > 同事件新增 Grade 2 直接证据 > Grade 1 背景补强 > 日期/顺序正确 > 重复与零增益惩罚 > 查询和调用成本。

Gold 仅在离线计算奖励时可见。STOP 还需检查 unresolved gaps，不能把一次低质量 query 的零收益误判为任务已经完成。
