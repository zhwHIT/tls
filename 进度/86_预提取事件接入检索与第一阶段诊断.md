# 预提取事件接入检索与第一阶段诊断

2026-09-20。用户要求默认接受大模型事件摘要的误差；检索仍针对文章，但不再返回原文，而返回已提取的事件与时间，并重测之前表现差的案例第一阶段。

## 实现

- 现有 `run_tisa_two_phase_annotation.py` 按 `preextracted_events.enabled` 分派新模式。
- 文章 BM25＋向量排序、top-k 和发表日期过滤保持原实现。返回内容由显式白名单投影为文章 ID、发表日期、抽取状态和事件日期/精度/摘要；不包含正文、原文片段、示例、原文证据引句。
- VERIFY 只判断主题相关性、时间线价值、重复事件归属，不重新提取、不修改日期/摘要、不要求逐条原文事实验证。
- 年、月、未知日期和时间区间均可保留在时间线；Gold 精确日期覆盖率只使用日级日期，不将年份转为 1 月 1 日。
- SEARCH 复用原人物职业生涯提示、早期边界探索、记忆压缩和线索轮转。日期精度不足的已接受事件可形成进一步检索提示，不因此被拒绝入线。
- 保留原先的请求账本、缓存、输入 token 限额、直连和断网暂停机制。新实验不运行第一阶段补充、第二阶段或最终筛选。

## 测试范围

按已有第一阶段审计选出的三个最低覆盖案例：David Beckham 0/16、Bill Clinton 4/47、Bashar al-Assad 3/24。属于 Gold 表现选出的诊断案例，不是未接触测试集，也不是等预算因果消融。

每例从空时间线开始，最多 24 批，每批最多 3 query，每 query top-12 文章。VERIFY 每次最多 8 条预提取事件，按 token 预算缩页，不截断摘要。三个主题独立进程并行。

- 配置：`chronos_repro/configs/preextracted_phase1_diagnostic_suite.json`
- 实验根目录：`chronos_repro/artifacts/preextracted_phase1_20260920`
- 状态：`suite_status.json`
- 最终对比：`comparison.json`
- 各主题：`trajectory.json`、`candidate_pool.json`、`event_pool.json`、`gold_date_coverage.json`

Gold 只在每个主题 rollout 结束后加载。除了主指标，还分别统计：全主题抽取结果可覆盖的日期、检索得到的日期、最终选择日期，以及 Gold 起止精确命中和跨度包含情况。

## 预检与运行修复

三个文章库存分别为 2,945、2,041、1,206，均与原索引文档 ID 完全一致。真实混合检索测试均只返回抽取事件投影。

首轮 API 出现同批候选相互引用的 MERGE 目标 ID。执行器现可将同批候选 ID 解析为实际时间线 ID，支持前向引用，但拒绝循环、被忽略目标及不同日期合并。两次已返回的失败批次通过缓存复用，不重新请求。Beckham 同期保存检查点暂停后一起续跑。

修复前的检查点、账本、评测与代码绑定保存在各主题 `history/before_batch_alias_repair`，代码变更与原因写入 `runtime_transition.json`。请求额度不重置，成本包含修复前调用。修复后相关测试 **52 passed**。

最终数字应以运行结束后的 `comparison.json` 为准；运行过程事件数不代表 Gold 覆盖改善，也不代表事实一致率。

## 最终结果

三例均已结束，没有运行补充阶段或第二阶段。运行过程中另修复 SEARCH 重复 query 的纠正提示超出 4K 预检的问题：新模式下直接使用已有代码去重恢复，保留新 query，全部重复时明确执行器停止。该次变更记录在 `runtime_transition.json` 和轨迹中，先前快照保存在 `history/before_policy_repair_budget_fix`。相关测试 **53 passed**。

总计 168 次 HTTP 请求，包含修复前调用；三主题成功返回累计 414,483 tokens。53 项本地测试通过。最终验收确认：仅第一阶段、运行代码与最终绑定一致、抽取文件未变、VERIFY 未包含原文字段、最终摘要与日期均来自原预提取条目、所有已返回请求输入低于 4096 tokens（观测最大 3658）。验收文件为实验目录下 `acceptance_checks.json`。
