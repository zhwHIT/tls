## 1. 轨迹不可变性

`model_step()` 对输入、输出、观察结果分别深拷贝，切断与活动状态之间的共享引用。后续增加 query、变更 gap 状态、更新模型输出对象，不会回写之前步骤。

每步新增快照元数据，明确这是步骤 payload 快照，不声称等于经过上下文投影后的真实网络消息。训练导出继续要求实际推理输入对齐、语义复核和数据拆分。

回归测试覆盖：记录第一步后修改嵌套 gap、查询列表、模型输出和 observation，再记录第二步；第一步序列化内容必须完全不变。

## 2. 日期冲突

新增来源局部上下文检查，并在三个入口使用：原文注释生成、片段注释附加、VERIFY 日期证据验证。

- 裸星期词与紧邻显式月日冲突时，拒绝该注释。
- “set for / scheduled for / will”等未来语境与过去的星期归一化冲突时，拒绝该注释。
- 不生成替代日期，不把发布日期直接作为事件日期。
- 附加旧注释时保留被拒绝的注释 ID 与原因，便于诊断。
- 提升 VERIFY 抽取缓存协议版本，避免沿用旧规则下的抽取结果。

历史事件不会被这个补丁自动改写或删除，仍需单独重审。上下文检查是保守的局部规则，并非完整的时态或篇章语义理解。

## 3. Gap 去重

对带有明确命名对象和年份、没有指代歧义的完全相同问题，允许跨锚点去重。对于“它是否获批”“谁在 2012 年获胜”等依赖上下文的问题，继续保留锚点区分；空问题不得合并。

历史重复 gap 不删除：将额外的 OPEN 副本标为 DEFERRED，并保存 `duplicate_of` 及审计链接。旧查询、批次数、gap ID 保留。去重不等于解决问题，也不会补造 RESOLVED 证明。

此轮仅实现保守的确定性去重，近义改写仍可能保留。没有调整轮数上限、VERIFY 次数或默认 query 数量。

## 4. 已有证明事件复用

复核 gap 时，在同一最多 12 条事件的窗口中优先保留锚点及相关已解决 gap 的证明事件，再按去除常见词后的加权词面匹配填充其他事件。

旧证明必须引用当前仍存在的事件、引文仍逐字存在、事件无 conflict 且仍有证据 ID。被删除、改写、冲突或无来源的证明不得复用。复用只改变可见证据，不自动解决当前 gap；模型仍需按当前完整完成条件判断。

输入不足时仍按原 3800 token 预检和 4096 token 硬限制缩减窗口。复用来源记录在独立审计字段中，不向模型反复输出相同的证明引文。
