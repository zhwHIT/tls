## 2. 错误不是 event-036 丢失

已读取父轨迹、续跑轨迹、两次实际模型响应及 token 请求审计。使用禁止联网的离线客户端重建请求并返回保存的响应，**两次请求哈希均与原始记录匹配**，复现相同错误。

结果：[Dilma 错误分析](../chronos_repro/artifacts/dilma_gap_failure_analysis_20260917.json)。复现脚本：[reproduce_dilma_gap_failure.py](../chronos_repro/analysis_tools/reproduce_dilma_gap_failure.py)。本次分析新增 API 调用为 0。

全局事件库保存 36 条事件，`event-002` 和 `event-036` 都存在：

- `event-002`：2016-05-12，参议院决定启动弹劾审判，Rousseff 被暂停总统职务。
- `event-036`：2016-05-11，参议员在弹劾投票前继续发言。

两条事件均不在第一段 GAP_DISCOVERY 的 12 条 `events` 窗口内，却都出现在同时提供的全局 `fact_memory` 中。

## 3. 两次调用如何失败

| 尝试 | 模型选择的锚点 | 全局存在 | 在本窗口 | 引文是否逐字匹配全局原事件摘要 |
|---|---|---|---|---|
| 首次请求 | event-002 | 是 | 否 | 是 |
| 修复请求 | event-036 | 是 | 否 | 否 |

首次模型从全局摘要提出“弹劾审判最终结果是什么”，引用 event-002。校验器只接收本窗口 `payload['events']`，因此报告 `gap neighbor does not exist: event-002`。

修复请求仍提供同样的窗口与全局摘要，只附加一般性报错和“返回完整修正 JSON”。没有明确列出允许的锚点集合或给出可用于修复的准确锚点摘要。模型换成摘要中另一个 event-036，仍不在窗口内，因此再次失败。

而且第二次引文来自摘要改写后的文本：模型使用 `senators continued speeches...`，事件本身写作 `Senators continue speeches...`。即使将校验范围扩大到全局事件，这次响应仍会因引文非逐字匹配而失败。离线复现也验证了这一点。

## 4. 根本原因与为什么重跑无效

1. **可见信息与合法锚点范围不一致**：模型看到全局摘要中的事件 ID，但只允许引用当前事件窗口；输入没有足够明确地分隔两者。
2. **摘要不等于逐字证据**：摘要会改变时态或措辞，但锚点引文必须匹配原事件摘要。
3. **修复信息不足**：没有给出允许 ID 及其精确文本，容易在多个全局摘要锚点之间换错。
4. **局部错误被提升为整个主题失败**：两次校验失败后抛出 LabelValidationError，由顶层捕获为 stopped_error，未隔离单个 gap/window。
5. **续跑没有改变这个契约**：父轨迹第一阶段已到上限，gap discovery 尚未成功。续跑恢复相同 36 条事件与摘要，再次从第一窗口发现 gap，因此重现问题。此次没有复用父 API 缓存，是两次新的实际请求，不能归因于缓存重放。

错误文本“不存在”实际是“不在传入校验器的当前窗口中”，措辞容易误导为全局事件缺失。

这次续跑新增 2 次 HTTP 尝试、4424 个记录 tokens，没有新增成功步骤，也没有新增事件。36 条旧事件完整保留。两次实际输入分别为 1909、2140 tokens，不是 4K 溢出导致的失败。

## 5. 后续应如何修复

- 明确区分背景摘要和可引用锚点。需要引用摘要事件时，先从事件库取回其准确事件文本，在 token 预算内加入明确的锚点列表，模型和校验器使用同一列表。
- 修复提示提供允许的锚点 ID 及准确摘要，避免只报一个“不存在”的 ID。
- 不应单纯改成校验所有全局 ID；允许一个 ID 不等于模型已经看到它的准确证据。
- 个别 gap/window 修复失败可隔离并继续其他窗口，但必须记录发现过程不完整，不能把失败当作“没有 gap”或“允许自主完成”。
- 为该实际保存请求增加回归用例，再决定是否续跑 Dilma。

已完成的 v9.9 隔离修复处理的是轨迹快照、日期冲突、gap 去重及 GAP_STATUS 证据复用；**尚未修复这里 GAP_DISCOVERY 的摘要/锚点范围契约**。本次按用户要求只做定位，未声称该错误已经解决。
