## 已完成的工程改动

### 1. 同目录独占运行

新增 `chronos_repro/src/chronos_repro/run_guard.py`。

主程序进入输出目录写入及执行阶段前获取操作系统文件锁：Windows 使用 msvcrt，其他平台使用 flock。第二个进程不能同时运行同一目录；正常退出、异常或进程终止后，操作系统释放锁。锁文件存在本身不代表任务仍在运行，因此不用删除陈旧锁文件解锁。

已测试跨进程互斥和异常后的释放。此保护接入主 CLI 与新批次入口；直接绕过 CLI 调用底层客户端仍不是完整的并发安全方案，不能宣称所有调用方式均受保护。

### 2. 重放归档和执行记录

coverage 运行明确禁止进入旧版 schema-v4 的局部恢复分支。已有轨迹、checkpoint 或请求账本时，必须显式选择 `--replay-from-start`。

执行前复制指定历史输出到 `history/<UTC时间>-<随机后缀>/`：包含轨迹、评测、checkpoint、配置、账本副本、事件池与训练候选。原累计账本和 API 缓存保留，不清零、不删除；不复制 `.env` 或任意用户文件。

新增 `execution_record.json`，标明 fresh 或 replay_from_start、checkpoint_resume=false、历史归档位置及开始时间。真正的第 7 轮断点续跑仍未实现；本项是让重放可审计，而不是把重放伪装成续跑。

已完成离线归档测试，但实际 Yemen 目录尚未执行本次归档，因为 API 批次启动命令被拦截。

### 3. 代码版本绑定

对项目 `src/chronos_repro` 和 `scripts` 下的 Python 文件计算内容哈希，生成 `code_binding.json`，运行标记为 `two-phase-v7-hardening1`。轨迹同时记录 source_sha256；没有修改原有主题配置及授权上限。

多主题评测校验记录内的代码指纹与轨迹一致。版本不一致或缺少代码绑定时，不输出可用于版本比较的总体指标。批次每开始一个主题之前也检查源码未变化。

这是源码内容记录，不是签名证明；尚未覆盖全部依赖版本、操作系统、硬件和外部模型服务变动。长时间运行时不得中途修改已绑定源码。

### 4. 串行诊断批次

新增 `chronos_repro/scripts/run_guarded_diagnostic_suite.py`。

默认只生成计划，未传 `--allow-api` 时不读取密钥、不构造模型调用。运行模式依次处理 Yemen、MJ、David Bowie，各自保留原输出目录和累计账本，并把日志写到新的批次记录目录。

任何主题返回错误时，批次先停止，留待分析；余额不足立即停止整个批次。重启同一批次记录目录会被拒绝，以免覆盖批次日志。

## API 启动受阻及待确认外发范围

环境安全审核认为，既有候选片段授权没有足够明确地涵盖此次完整轨迹 payload 和规模。因此命令在进程创建前被拒绝。没有通过其他脚本、间接执行或缩写参数绕过。

拟使用的范围：

- 接收方：`https://api.deepseek.com`，模型 `deepseek-v4-flash`。
- 数据：Yemen、MJ、David Bowie 冻结语料；每次检索选取最多 8 段，每段正文最多 3200 字符，可附前置上下文最多 400 字符。
- 额外输入：标题、段落 ID 与元数据、query、memory、候选事件、当前时间线、引用证据及用于修复的历史模型响应。
- 分页、VERIFY、MERGE、memory 更新和重试可能重复发送上述内容；每段上限不是整次 HTTP payload 或总外发字节上限。
- 不将 private gold 时间线发送给模型；gold 只用于本地事后评测。
- 剩余最多 1123 次 HTTP 请求，分主题上限不变；余额不足立即停止全部调用。

这会把语料内容及派生状态交给第三方服务，并产生模型调用费用。需要用户对上述完整范围明确确认后再尝试启动。

机器可读阻塞记录：`chronos_repro/artifacts/tisa_v7_hardening_batch_01/authorization_blocked.json`。该文件记录状态，不授予权限。
