# 截至目前的操作、动机与结果总结

> 更新时间：2026-09-04  
> 当前阶段：数据、评测、闭域快照、统一 BM25 检索和轨迹重放已完成；尚未开始正式 LLM 时间线生成及 SFT/DPO 训练。

## 一、目标与动机

项目目标是在 CHRONOS、R2A-TLS、TISER、MAS-TLS 基础上构建时间线状态驱动的 Search Agent：

```text
当前时间线状态 → 识别日期/因果/事件要素缺口
→ SEARCH / VERIFY / MERGE / STOP
→ 检索并验证证据 → 更新时间线 → 判断继续或停止
```

计划先以 SFT 学习状态、查询、证据选择和停止动作，再以 DPO/SimPO 优化同一状态下的好坏决策。训练前优先建设数据、评测和检索底座，是为了保证每个结果都能追溯到确定的数据、代码、文档、动作和指标后端。

## 三、Open-TLS 读取与评测

实现了安全读取器，支持 Open-TLS、CHRONOS `predict-timeline`、多种预测结构和日期格式。上游任意 `eval()` 被替换为 `json.loads()`，只对旧 Python literal 使用安全的 `ast.literal_eval()` 回退。

Open-TLS 审计通过：50 个主题、1,130 个累计唯一日期、2,070 个累计事件。实现了 Date Precision/Recall/F1、Tilse Timeline-ROUGE、单主题和批量评测、跨主题 macro mean。输出记录 commit、快照、预测 SHA-256、后端、平台和耗时。

金标准回灌时，单主题和 Open-TLS 50 主题批量 Date P/R/F1 均为 1.0。这只证明读取和指标管线正确；因为预测来自金标准，存在完全泄漏，**不能作为模型 baseline 或论文结果**。

当前 Windows 没有 WSL/Linux，严格论文可比的原版 Perl ROUGE 尚未验证；`reimpl` 只用于开发回归。

## 五、统一闭域 BM25

使用 SQLite FTS5/BM25 建立本地索引，无新增第三方依赖。索引包含 topic、doc ID、标题、正文和时间；标题权重 2.0、正文权重 1.0。接口支持 `crisis <topic>`、`t17 <topic>`、`entities <topic>`，并核对数据集和主题以防静默错配。

| 数据集 | 索引文档数 | 索引大小 |
|---|---:|---:|
| Crisis | 17,573 | 142,721,024 bytes |
| T17 | 4,203 | 41,431,040 bytes |
| Entities | 51,183 | 385,081,344 bytes |
| 合计 | 72,959 | 569,233,408 bytes |

已完成 Crisis/Egypt、T17/Syria、Entities/Al_Gore 真实检索烟测。选择 BM25 是为了先获得稳定、低成本、可解释且不受在线搜索波动影响的基线，再引入 dense/hybrid retriever。

## 六、固定配置与轨迹

配置文件为 `chronos_repro/configs/retrieval_baseline_v1.json`：top-k 20、最多 3 轮、每轮最多 3 个查询、连续 2 轮无新增文档停止、按 doc ID 去重。生成温度为 0，但模型和 Prompt 仍为 `null`，尚未选择。

每轮保存：

```text
state → action {query, top_k}
→ observation {results, new_doc_ids}
→ updated_state {seen_doc_ids, document_count, new_document_count}
```

轨迹同时保存索引 SHA-256、snapshot、固定参数和停止原因。`replay-search` 会检查索引哈希并重跑每轮查询，任何变化都会失败。真实 Crisis/Egypt 三轮轨迹已逐轮重放一致，停止原因为达到 `max_rounds=3`。

动机是为 SFT/DPO 保留“在何种状态采取什么动作、看到哪些证据、产生多少新增信息”的训练依据。
