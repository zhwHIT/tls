# 最终答复纠错与统一验收口径

日期：2026-09-17。本次重新核对原始评测报告、当前配置、请求实现及第 59 份进度。以下纠正的是对话最终答复中的错误，不改变历史评测数据，也不构成新的在线评测。

## 1. 撤回的结论

1. 撤回“VERIFY 改动不会降低 Gold 覆盖率”。359 项离线测试通过，只说明所覆盖的本地测试成功；2651 个历史初始输入的 token 预检，只说明这些重建输入通过门槛。二者均不能证明新的线上召回、精度、完成率或费用变化。
2. 撤回“整体计划完成率为 12/18＝66.67%”。53 项计划中完成 12 项，计划完成率为 **12/53＝22.64%**。66.67% 是 **12/18 的已尝试任务成功率**。
3. 撤回“VERIFY 的费用占比为 56.63%，VERIFY 与 MERGE 费用合计占比为 71.29%”。这些是已记录 token 数的占比，没有对应历史费率、折扣及账单证据支持费用占比。
4. 撤回“发布日期直接补齐事件日期”。文章发布日期本身不能确定事件日期。缺少足够日期证据的候选不得直接成为日级事件。
5. 撤回“格式或引用修复不会增加模型请求”。本地检查不调用模型；请求模型修复可能增加调用，传输重试还会增加 HTTP 尝试。
6. 撤回按四次总传输尝试推导出的 8、16、48、96 上限。max_retries=4 是首次请求加四次重试，共至多五次尝试。

这些错误不作为“近似”“模拟”或“草稿”保留。历史运行是真实 API 评测，必须按实际统计口径报告。

### VERIFY HTTP 上限

当前每页允许一次初始调用加一次标签修复，每次逻辑调用最多五次传输尝试：**每页最多 2×5＝10 次 HTTP 尝试**。

| 范围 | HTTP 理论上限 |
|---|---:|
| 第一阶段一个片段，最多一页 | 10 |
| 第二阶段一个片段，最多两页 | 20 |
| 第一阶段一个搜索批次，至多三个查询、每查询两个片段 | 60 |
| 第二阶段一个搜索批次，同样至多六个片段 | 120 |

表内只计 VERIFY。缓存、去重、提前结束及错误停止可能降低实际请求数；HTTP 尝试数不等于成功生成次数。

### 金额计算条件

按相应模型和生效日期分别计算：

> 费用＝（缓存命中输入 tokens×命中输入单价＋非缓存输入 tokens×非缓存输入单价＋输出 tokens×输出单价）÷1,000,000。

单价单位为每百万 tokens。prompt_tokens 已包含缓存命中部分，不能重复相加。费率和失败请求 usage 未核实前，金额及金额占比保持未知。
