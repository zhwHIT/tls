## 修改后的流程

第一阶段：公开 topic/keywords → 模型 SEARCH → BM25+dense 混合召回 → 连续片段读取 → 分批 VERIFY → APPEND/UPDATE/DROP → evidence memory 更新 → 模型继续发散或 STOP。

第二阶段：当前时间线与 exploration memory → GAP_MEMORY → 单个 gap 的 SEARCH 或空查询 → VERIFY/MERGE → 保留所有新候选与未定日期线索 → 更新 gap、保留新增 gap → 继续或 STOP。

最后：SELECT 只选择已有事件、不改写事实 → 独立保存 event_pool 和最终时间线 → 本地日期评测、证据审计与词汇/ROUGE 诊断。

`extraction_complete=true` 是模型的完成声明，不是独立验证的“绝无遗漏”。达到分页上限且未完成时，保留未完成记录。lead 只有与正式事件摘要完全一致时才自动标记解决，近义改写可能仍保持 OPEN；不能用相似词自动认定事实得到证实。
