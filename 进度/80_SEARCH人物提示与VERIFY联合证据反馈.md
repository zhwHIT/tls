# SEARCH 人物提示与 VERIFY 联合证据反馈

日期：2026-09-18。状态：代码已修改，离线检查完成；未启动 API，未重算模型输出或 Gold 覆盖率。

## 修改范围

- SEARCH 增加人物生涯起点、职业变化、成就荣誉、事故伤病及恢复、法律与公益事件、退役和后续发展的通用检索方向。它们不是必须存在的事件，更不是从 Gold 复制的清单。
- SEARCH 接收每条未充分线索的 `reason`，要求针对缺失的日期分量、时间锚点、事件与日期关系、实际结果或冲突证据生成查询。
- `pending_leads` 不再固定取哈希排序前四项。默认每次最多 8 条，按展示次数和最近展示轮次轮转，同等条件再比较优先级；预算不足时缩小页面，但不截断理由。展示次数在实际策略调用返回后记录。
- 查询可通过 `target_lead_ids` 绑定当前可见线索；实际检索后写入 `attempted_queries`，无返回结果也不关闭线索。
- VERIFY 联合读取已经选出的同文片段，以及来自相关未充分候选的已读原始证据。默认最多 4 段、6000 个源文本字符，并以现有 token 预算预检进一步缩小组合。保持原文片段 ID、偏移和引用边界，不伪造连续引文。
- 同一篇冻结文章的另一已提供片段，可以通过明确原文年份补全年份；必须引用两段，文章 ID 和正文哈希一致。不得把发布年份或另一篇文章的年份直接补入。
- VERIFY 必须总结事件和时间；组合证据充分时输出现有 `SUPPORTED` 状态，经 MERGE 的 APPEND/UPDATE 进入时间线。重复事实仍可由 MERGE DROP，不是每个充分候选都增加一个节点。
- 不充分时仍使用 `INSUFFICIENT`，`reason` 要说明已知信息、具体缺口、所需证据。代码校验 reason 为非空有效字符串，语义详尽程度仍依赖模型遵循提示。
- 新增 `revises_candidate_ids` 关联原未充分候选，检查只能引用本次提供的候选及其原始证据。只有重新验证且被 MERGE 提交为同日期、无冲突事件，才据此关闭旧线索；原候选状态保留用于审计。
- VERIFY 缓存协议升级，避免复用旧提示词的抽取结果。历史运行配置及检查点不改写。

## 用户要求核对的四项

1. `candidate_pool` 保留经校验的全部返回候选，包括 IRRELEVANT。进入 MERGE 的 accepted 要求 SUPPORTED/CONFLICTED 且 relevance_pass、contribution_pass 都为真。待补证队列只收相关的 INSUFFICIENT。IRRELEVANT 不是在输出前删除。
2. lead ID 是 time + 标准化 summary 的哈希，是精确键去重，不是语义事件聚类。近义描述仍可有不同 ID。MERGE 的事件合并/去重与 lead ID 去重是不同步骤；176 个 lead ID 不代表 176 个独立语义事件。
3. 当前声明的 schema 没有 `missing_fields`，本次也没有新增它；缺口使用 reason。新增的字段是查询 target_lead_ids 和重验证 revises_candidate_ids。
4. 停止快照的 24 个时间线事件均有 date_evidence，且其中含 time_expression。构成：1 个直接完整日期，2 个显式日期冻结标注，14 个相对日标注，7 个星期标注。结构校验通过不等于事件日期语义正确。INSUFFICIENT 的 time=null 可以没有 date_evidence。

历史 event-017 的引文包含 `Saturday week`，而时间标注只选择 `Saturday`，已列为语义复核疑点；本次未修改该事件或其日期。

## 明确撤回的历史判断

- 2007 年签约 Galaxy 不等于 2007-07-21 首次代表 Galaxy 出场。
- 2011 年 MLS Cup 冠军不等于 2012-12-01 最后一场 Galaxy 比赛。
- MLS 联赛首秀也不能直接等同于首次代表 Galaxy 出场。
- 不能通过修改这些事件的日期，把 Gold 覆盖率从 1/16 计为 3/16。
- 合法且与事件关联一致的冻结相对时间标注可以作为日期依据；不是必须在原文中同时写出完整年月日。标注不能单独证明事件已实际发生。
- 缺日期用发布日期、缺年份用发布年份、计划过期视为已发生、日期冲突选最新报道，均不是有效的自动补证规则，未实施这些规则。
