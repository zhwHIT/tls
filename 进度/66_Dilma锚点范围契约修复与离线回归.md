# Dilma 锚点范围契约修复与离线回归

日期：2026-09-17。按照用户要求修复进度 65 定位的 GAP_DISCOVERY 报错，并保留 Snowden 结束后暂停、不自动启动后续主题的约束。

## 更正错误原因

此前答复把错误归因于“4K 限制触发裁剪”，这个说法错误。原始两次输入分别为 1909、2140 tokens，没有达到 4K。固定 12 条事件窗口与全局摘要的引用范围不一致，才是锚点校验失败的直接原因。第二次响应还有引文非逐字匹配的问题。

## 修复内容

1. **统一可引用范围**：每个发现窗口将保留的摘要事实所引用的事件准确文本加入 `events`，并提供 `allowed_anchor_ids`。模型与校验器使用同一集合，`discovery_window_event_ids` 区分原始扫描窗口与补充锚点。
2. **控制输入大小**：若超出 token 预检，先同步减少摘要事实及其额外锚点，再缩小扫描窗口；不保留一个摘要引用却不给它合法锚点文本。未知事件 ID 的摘要事实不进入该请求。
3. **可操作的修复提示**：错误带回允许的锚点 ID，明确只能逐字引用 `events[].summary`，不能引用摘要改写后的措辞。没有足够依据时允许输出空 gap，不允许猜 ID 或改写引文凑校验。
4. **隔离局部失败**：标签修复耗尽后，逐条验证并保留合格 proposal，隔离不合格内容，继续处理后续窗口。恢复生成的记录明确不作训练目标。
5. **不把失败冒充完成**：存在失败窗口时记录 `discovery_incomplete_windows` 与历史隔离记录；没有其他可处理 gap 时结束原因为 `gap_discovery_incomplete`。顶层输出 `stopped_incomplete_gap_discovery`，不进入成功主题统计。
6. **显式续跑可重试**：重新启动一个不完整发现任务时重新检查发现窗口；同一次运行不因空结果无限重试同一版本状态。

此次补丁同时包含此前隔离完成的轨迹快照、日期冲突、gap 去重、已有证明复用与训练门禁修复。没有提高 VERIFY 次数、阶段轮数或请求预算。
