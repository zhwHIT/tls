## 1. 本轮目标与边界

保持“全局骨架探索 → 局部 gap 修复”的两阶段架构，使用已授权 DeepSeek API，分析错误并提高严格 gold 日期召回。调用模型为 `deepseek-v4-flash`，密钥只从项目 `.env` 读取，不写入本文或新代码。

每主题跨重启累计最多 400 次 HTTP 请求，余额不足停止全部后续调用。自主流程不发送 gold；gold 只用于本地诊断与评测。诊断主题已被反复检查，不能称为未接触测试集。

## 4. 为什么覆盖仍不足

三个主题并不等价：Yemen 有 81 个参考日期，涉及密集的危机进展；MJ 有 38 个参考日期，本次检索命中的材料大量围绕死亡调查与庭审；David Bowie 只有 6 个参考日期，跨度为 1996–2016，属于稀疏的回顾节点。小主题的高分会显著抬高宏平均，因此需要同时列出每主题结果和微平均，不能只挑一个平均数。

1. 查询意图与结果进度没有充分区分：搜索“早期背景”返回其他时段的新事件，也会增加全局 gain；但原来的意图仍未回答，memory 可能重复追问。
2. 第二阶段部分 gap 偏背景与因果问题，不必然对应新的日期节点。应区分“关键阶段缺失”“日期/来源冲突”和“解释性信息不足”，分别评测增益。
3. MERGE 存在跨日去重损失：v8.2 VERIFY 命中 27 个参考日期，合并后 24 个。但计划日期、宣布日期及矛盾报道不能为增加召回全部保留。
4. 上游日期标注需要严格质量控制；来源绑定通过并不意味着年份或事件修饰关系一定正确。
5. 真正 checkpoint 续跑尚未实现，当前是保留账本的缓存重放。prompt 改变会导致新请求，因此修复顺序和缓存利用很重要。
6. 粗骨架与精确日期的要求仍耦合过紧：人物语料中只有年份的阶段会因无法进入日粒度 verified timeline 而被反复视为缺失。后续应单独保存带来源与精度的粗粒度阶段证据；这不意味着把年份补成元旦，也不意味着放宽最终 gold 日期匹配。

David Bowie 实测还暴露了具体的 weekday 风险：文档 22081 的发布时间是 2012-01-06，描述其在 Sunday 迎来 65 岁生日，上游归一化为此前的 2012-01-01；模型沿用并写成已发生事件。同一轨迹另有 1947-01-08 的出生日期，与该生日日期不一致。当前原文/ID/日期锚点契约可以通过，但不能证明 Sunday 的前后方向及事件时态正确。

不能为追求召回率直接把该日期改成另一周日。需要先用原文时态、明确年份/日期或独立证据消歧；无法确认时应保留待核实/冲突状态。这是未修复的语义校验风险，不能将本轮产物直接作为高质量训练标注。

### 下一步 memory 修复的具体方向（尚未实现）

将“是否搜索过”与“是否得到答案”分开，而不是用一段容易过时的 boundary_assessment 承担两者：

```json
{
  "direction": "一个可检索的阶段、边界或事件问题",
  "status": "UNTRIED | PROBED_UNRESOLVED | SUPPORTED | DEFERRED",
  "attempted_query_ids": ["q-003", "q-006"],
  "supporting_event_ids": [],
  "unresolved_reason": "检索到其他阶段的新事件，但当前问题仍缺直接证据"
}
```

这是 memory 内部的轻量状态，不需要让每个工具变成独立训练模型，也不需要把完整历史或 gold 放入控制器。全局 new_event_count 可保留作成本诊断，但不能直接等同于该 direction 的完成度。首先在本地轨迹上验证标注规则，再选择有剩余授权额度的主题做 API 对照；不能重置 Yemen 的 400 次账本。
