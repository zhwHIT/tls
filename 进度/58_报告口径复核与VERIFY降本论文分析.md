## 1. 结论与历史答复更正

报告必须同时给出日期召回的微平均和宏平均，注明样本范围、版本、完成情况和停止原因。此前最终答复中的指标名称与分数配对有误；现有聚合代码和第 57 份进度文档采用的微、宏平均定义正确。

| 范围 | 日期命中/Gold 日期 | 微平均召回 | 宏平均召回 | 使用限制 |
|---|---:|---:|---:|---|
| v9.5 T17 九主题快照 | 281/573 | 49.04% | 64.85% | 只有 7/9 状态 ok；包含两项中断快照，正式 aggregate 为空 |
| 最新 T17：原七主题 + v9.7 Haiti/Iraq | 282/573 | 49.21% | 64.92% | 九主题均有 ok 结果，但混合版本、继承状态，仅作开发进度诊断 |
| 本轮 v9.7 T17 两主题 | 46/166 | 27.71% | 61.29% | 仅 Haiti、Iraq，不能标为全 T17 |

需要明确更正的历史说法：

- “64.85% 按全部 Gold 日期加权”错误：64.85% 是主题等权的宏平均，按 Gold 数量加权的是 49.04%。
- “整体覆盖率 64.92%（282/573）”错误：282/573 对应 49.21%；64.92% 是另一个指标，不能共用该分数表达式。
- “7/9＝87.5%”错误：应为 77.78%，第 55 份进度已更正。
- “VERIFY 不限，因此请求预算不再影响完整性”错误：非 VERIFY 预算、余额、阶段上限及输出校验仍能停止流程。
- 状态 ok 代表执行完成，不等于模型自主停止，也不等于事件语义已经验证正确。

可核验的依据为原始 JSON、当前代码及已有进度记录。历史聊天中未保存在工作区的原始工具消息不能逐条重放；本报告不声称恢复了这些消息的完整日志。

## 2. 微平均和宏平均怎样解释

对主题 i，G_i 是该主题各参考时间线日期的并集，P_i 是预测日期集合，h_i＝|G_i ∩ P_i|，g_i＝|G_i|，r_i＝h_i/g_i。

- **微平均：Σh_i / Σg_i。** 每个“主题—Gold 日期”同等权重，回答全部参考日期总体命中了多少。等价于以 g_i 为权重平均各主题召回。
- **宏平均：(1/N)Σr_i。** 每个主题同等权重，回答平均一个主题的召回表现如何。

例如 Haiti 为 11/11、Iraq 为 35/155：宏平均是 (100%＋22.58%)/2＝61.29%；微平均是 46/166＝27.71%。Haiti 日期少、召回高，Iraq 日期多、召回低，所以这组宏平均更高；两者一般不存在固定大小关系。同一天出现在不同主题中，仍分别计数。

建议报告固定使用以下列，不根据结果选择较高的一项：

> 数据集 / 运行版本与是否续跑 / 完成数÷计划数 / 命中÷Gold / 微平均日期召回 / 宏平均日期召回 / 日期精度及 F1 / 自主停止数 / 上限、错误、余额停止数。

“总体 Gold 日期覆盖”用微平均，“主题平均表现”用宏平均。正式论文主表同时呈现两项。对多个数据集分别报告；不将三种数据集混成一个未说明权重的数字。存在失败或未开始主题时，保持当前正式 aggregate 为空；可另外明确列出中间快照，不能只挑成功主题代表全数据集。

当前统计是 **reference-union 日期召回**，不是语义事件覆盖。论文中的 Date F1 同时考虑日期精度和召回，且多参考时间线的评测约定需要逐项对齐，不能直接拿本项目的 49.21% 或 64.92% 与其 Date F1 比大小。CHRONOS 的评测定义见[原论文 §5.2](https://aclanthology.org/2025.findings-naacl.248.pdf)。

## 4. VERIFY 开销的实际构成

复算范围：v9.7 当前 18 个主题目录，仅统计本轮轨迹；请求账本扣除 T17 继承的历史请求。

| 项目 | 数量 | 含义 |
|---|---:|---|
| 本轮全部新增 HTTP 请求 | 6794 | 含失败及重试 |
| VERIFY HTTP 请求 | 3342 | 约占全部请求的 49.19% |
| 非 VERIFY HTTP 请求 | 3452 | 不能忽略的另一半开销 |
| 轨迹 VERIFY 步骤 | 2651 | 逻辑步骤，不等于 HTTP 次数 |
| 片段出现次数 | 2651 | 本轮每步骤一个片段 |
| 各主题内去重后片段数之和 | 1992 | 不跨主题合并 ID |
| 重复片段出现次数 | 659 | 不能直接当成可删除请求 |

659 次重复中，639 次上一次没有标记抽取完成；其余 20 次虽标记完成，却正好达到候选上限，因此执行器保守地保留为未完成。561 次发生于同阶段，98 次跨阶段。当前存在未完成抽取后的重入，而不是简单地“所有已完成片段又验证了一遍”。

请求口径已交叉核对：token_usage_audit 中 VERIFY 的 http_attempts 合计 3342，与账本一致。轨迹 audits 合计为 3333，少 9 次，说明仅统计轨迹中返回的审计结果会低估请求数；不能把差值归为没有发生的请求。

VERIFY 成功响应已记录的输入 tokens 为 5,141,072，输出 tokens 为 1,301,868；输入中缓存命中 529,920、未命中 4,611,152。此处不推算缺失 usage 的失败请求费用，也不把请求占比当费用占比。

实现核验：

- VERIFY 同时承担候选事件抽取、主题相关性、日期证据与结构校验。删除它会删除主要抽取路径。
- 当前配置 verification_batch_passages＝1、candidates_per_batch＝6；第一阶段每批最多一页、第二阶段最多两页。增加片段数时必须同步考虑候选容量与输出长度。
- 已有抽取缓存、API 缓存和已读标记，不能笼统说“没有缓存”。抽取缓存键包含片段对象、阶段、已提取事件等状态；需要区分真正改变任务的上下文与无关排序元数据。
- 只有抽取完成且未达到候选上限才标记已读。未完成项需要有明确的进度与再次尝试条件，不能为省请求直接标成完成。

## 5. 其他论文采用什么办法

以下是已查阅原文的机制；右列是本项目的应用建议，不是论文已经验证过本项目的效果。

| 论文 | 原文机制 | 对本框架的启发和边界 |
|---|---|---|
| [R2A-TLS，§3.1、附录 Listing 3/4](https://aclanthology.org/2025.findings-emnlp.40.pdf) | 初始前三篇生成种子时间线；其余文章先判断主题相关性，再判断信息增益，通过后才生成片段时间线；反思后定向补充 | 在昂贵抽取前过滤明显无关或无新增证据的内容。其过滤本身采用模型提示，不能认为免费；逐篇增加两次同价 API 判断可能反而增加费用 |
| [CHRONOS，§3.3](https://aclanthology.org/2025.findings-naacl.248.pdf) | 每轮生成局部时间线，最后合并、处理日期及描述冲突 | 借鉴按批抽取、后续合并，减少小请求。论文没有与本项目严格日期校验完全相同的独立 VERIFY 协议，不能据此省略证据检查 |
| [CRAG，§4.2–4.4](https://arxiv.org/html/2401.15884v3) | 微调较小的 T5-large 检索评估器，按置信度采取不同处理，并压缩为相关知识片段 | 可用较小本地模型做相关性筛选，不确定项交给完整抽取；相关性判断不等于事件日期成立。其开放网络检索也不应直接引入当前冻结闭域语料评测 |
| [Self-RAG，§3.2](https://arxiv.org/html/2310.11511v1) | 离线用 critic 标注反思信号，再训练生成模型，使推理时能自行输出这些信号，无需另调 critic | 长期可蒸馏筛选或证据支持判断，减少独立大模型调用；需要数据和训练，不能通过给现有 API 加几个标签就获得同等能力 |

这些论文的验证对象不完全相同：检索相关性、输出支持度、时间线事件抽取不能混为一谈。没有找到可以直接保证本框架“删掉 VERIFY 而不损失质量”的依据。现有四篇已经覆盖筛选、批处理、轻量评估与蒸馏，足以形成下一步方案，本轮停止继续扩展检索。

## 6. 建议的改进顺序与实验边界

1. **先管理未完成抽取和重试。** 稳定保存每个片段已抽出的事件、未完成原因及进度。相同输入且没有新进展时避免立即原样重试；保留待补读状态，不能虚报已完成。纯格式错误尽量局部修复，保留已通过的候选。
2. **尝试 1–2 片段动态批处理。** 用现有 DeepSeek tokenizer 对完整请求计数，保留约 4K 输入约束；候选多、证据长时退回单片段。批量上限、候选上限、日期引文及输出长度一起检查。此处只能提出待测方案，不能预先宣称请求减半或覆盖不变。
3. **增加保守的相关性与证据增量筛选。** 精确重复内容先本地复用；低成本筛选只排除高置信度无关项，不确定项继续抽取。判断新增信息时同时看事实摘要和未汇总的 verified events，避免延迟 memory 造成误判。不要因为某日期已有事件就删除同日新事件，也不要只因片段没有显式日期就删除可由上下文定年的证据。
4. **已有证据复用，冲突与新增证据再审核。** 缓存键保留主题、文本、时间锚点、提取协议版本和真正相关的任务状态，去掉不影响证据判断的排序分数。跨阶段抽取目标不同，不能无条件共用完成结论。
5. **蒸馏 verifier 作为后续可选扩展。** 毕设当前学生目标仍是根据摘要、事件增量和 gap 输出 SEARCH/STOP；不把抽取和 verifier 训练悄悄加入当前必做范围。

上述建议与“摘要整理事实、无可操作 gap 可停止、MEMORY_UPDATE 不必逐次 SEARCH 触发”兼容。过滤结果只决定是否值得读，不自动制造 gap；延期或没有新证据也不等于已经解决 gap。

验收应固定语料、版本、输入上限和停止口径，逐项消融；分别报告微/宏日期召回、日期精度/F1、候选证据抽查、完成率、HTTP 次数、输入输出 tokens、重试次数及耗时。Gold 只用于事后评测，不用于筛选阈值或在线搜索决策。取消 VERIFY 硬次数上限的用户要求保持不变。
