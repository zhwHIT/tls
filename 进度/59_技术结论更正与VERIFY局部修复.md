### 重试上限的准确范围

配置 label_repair_attempts=1：一页最多两次逻辑生成调用。每次逻辑调用最多五次 HTTP 尝试。因此一页最多十次 HTTP 尝试。

| 范围 | 逻辑生成调用上限 | HTTP 尝试上限 |
|---|---:|---:|
| 第一阶段，一个片段，最多一页 | 2 | 10 |
| 第二阶段，一个片段，最多两页 | 4 | 20 |
| 第一阶段，一个搜索批次，至多三个查询、六个片段 | 12 | 60 |
| 第二阶段，一个搜索批次，至多三个查询、六个片段 | 24 | 120 |

仅计算 VERIFY。HTTP 尝试数不是成功模型输出数；缓存、提前完成、余额错误和其他中断可降低实际数目。VERIFY 全局不设请求硬上限的要求保持不变。

已检查 coverage_preflight 的预算口径：使用真实累计账本，并把非 VERIFY 预算与 VERIFY 分开；没有把上述旧答复中的 96 或 49% 写成执行上限。本轮没有据错误估算增加 API 额度或调整已有运行账本。

### 费用模型与重新核账

在同一有效价格口径下：

> 费用＝（缓存命中输入 tokens × 命中输入单价 ＋ 非缓存输入 tokens × 非缓存输入单价 ＋ 输出 tokens × 输出单价）÷ 1,000,000。

价格单位为每百万 tokens；若模型、日期或折扣不同，应分组计算后求和。prompt_tokens 已包含缓存命中输入，不能再加一次命中 tokens。没有 usage 的失败请求不默认免费。

VERIFY 已记录：命中缓存输入 529,920、非缓存输入 4,611,152、输出 1,301,868 tokens。其总 tokens 为 6,442,940，占全部已记录 tokens 的 56.63%。目前没有已核实的历史价格与账单，所以不填写金额或金额占比。

新增[离线费用口径审计脚本](../chronos_repro/analysis_tools/audit_verify_costs.py)与[复算结果](../chronos_repro/artifacts/verify_usage_cost_audit_20260917.json)：账本 6794 次请求，分阶段 usage 审计可归属 6792 次；另两次在 Dmitry Medvedev 余额停止任务中未获得对应 usage。结果将 monetary_cost、monetary_share 明确设为 null。

## 2. VERIFY 已实现的改进

### 保留有效候选，只修复失败项

- 新增 verify_partial_repair 模块，先逐条校验候选。有效项保留在本地，修复提示仅包含失败候选、错误信息及必要原文。
- 用 repair_index 明确修复槽位；修复不能改写有效项、冒用已有候选 ID、插入未请求槽位或遗漏槽位。
- 只有 thought 等批次元数据出错时，修复输出不必重发全部候选。
- 修复仍失败时，保留已通过的候选，隔离失败项，标记 extraction_complete=false；修复请求触发 token 门禁时同样保留已验证项。
- 无法解析的整份 JSON 没有可可靠定位的候选，仍允许一次整份响应重试。不能声称已消除所有整批重试。
- 修复不会把原本声明未抽完的片段改成抽取完成。拼接修复结果和隔离结果不作为未经区分的模型训练正例。
- JSON 解析失败的已返回响应保留 usage 审计，避免漏掉实际返回但格式错误的调用。

### 减少无变化的重复抽取

- 抽取输入移除 reader_score、reader_origin、reader_date_filter 等检索选择元数据；保留真实正文、上下文、时间标注和证据来源。
- already_extracted 精确去重并稳定排序，缓存键保留阶段、模型、协议版本和相关参数。
- 同一证据和抽取状态可复用缓存；正文、时间标注、阶段等变化仍产生不同请求。
- 候选 ID 不再因重入时分页编号变化而变化；已经提交 MERGE 的同一候选不再次送入 MERGE。
- 缓存写入检查点及最终轨迹，续跑可恢复；历史没有该字段的运行保持兼容。
- 未完成抽取仍留在未完成记录中；缓存命中不伪装成抽取完成，重复未完成记录和缓存隔离记录不反复堆积。

### 控制重复输出

提示词要求 reason、thought 不重复引文，使用仍能支持事件和日期的最短逐字证据，不无故复制整段。没有程序性截断引文，没有放松日期/引用检查，也没有按日期合并不同事件。这里只改变输出要求，尚未实测新输出 token 降幅。

## 3. MERGE 已实现的改进

模型调用前进行保守的确定重复检查：日期、摘要、人物、地点、日期证据、置信度一致，候选没有新来源证据，并且不存在冲突时，才本地生成 DROP。

- 整批都属于确定重复：不调用 MERGE 模型。
- 只有部分重复：仅把其余候选发送给模型，最后与本地 DROP 合并执行并记录来源。
- 同批重复候选保留一个代表。
- 日期不同、同日不同事件、新来源、新日期引文、冲突和其他字段变化仍交给模型。
- 本地及混合生成的操作标记为非纯模型训练目标；候选原始证据仍保留在候选池中。

这种判定刻意保守，不能把全部历史重复片段数当作可省去的请求数。
